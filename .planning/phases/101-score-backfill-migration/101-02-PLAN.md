**schemas.py changes:**
Add two optional fields to `ParcelAtPointResponse` after `score_breakdown`:

```python
potentie_score: float | None = Field(
    default=None,
    description="Potentie subscore (0-100) from v3.0 scoring model",
    ge=0, le=100,
)
risico_score: float | None = Field(
    default=None,
    description="Risico subscore (0-100) from v3.0 scoring model",
    ge=0, le=100,
)
```

**router.py changes:**
Find the score extraction logic in `_build_parcel_at_point_response()` (or wherever `score_breakdown` is populated from `flags`). The research identifies this at lines ~1759-1772.

Replace/augment the extraction with v3.0-first detection:

1. Initialize `potentie_score = None`, `risico_score = None`
2. Check for v3.0 format FIRST:
   ```python
   v3_breakdown = scan_flags.get("score_breakdown")
   if isinstance(v3_breakdown, dict):
       first_val = next(iter(v3_breakdown.values()), None)
       if isinstance(first_val, dict) and "categorie" in first_val:
           # v3.0 format
           score_breakdown = v3_breakdown
           v3_scores = scan_flags.get("scores")
           if isinstance(v3_scores, dict):
               potentie_score = v3_scores.get("potentie")
               risico_score = v3_scores.get("risico")
   ```
3. ELSE fall through to existing v2.1 logic (`flags.get("factors")` path)
4. Pass `potentie_score` and `risico_score` to `ParcelAtPointResponse` constructor

Also check if there's a scan results list endpoint that builds score_breakdown -- apply the same v3.0 detection there.
