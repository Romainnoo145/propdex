```python
"""MVT tile proxy with multi-tenant filtering.

Proxies tile requests to Martin tile server, adding organization_id
filtering to prevent cross-tenant data leakage.

Martin serves the entire parcel_cache table. This proxy:
1. Validates scan ownership (scan belongs to requesting org)
2. Forwards tile request to Martin with appropriate filters
3. Returns MVT binary response

Per research pitfall #3: NEVER expose Martin directly to frontend.
"""

import uuid
import httpx
from app.core.config import get_settings

async def fetch_tile(
    z: int,
    x: int,
    y: int,
    organization_id: uuid.UUID,
    scan_id: uuid.UUID,
    http_client: httpx.AsyncClient,
) -> bytes | None:
    """Fetch MVT tile from Martin with organization filter.

    Uses Martin's query parameter filtering to scope tiles
    to specific organization and scan data.

    Args:
        z, x, y: Tile coordinates
        organization_id: Tenant UUID for data isolation
        scan_id: Scan UUID to scope results
        http_client: Shared httpx client

    Returns:
        MVT binary data or None if no data for tile
    """
    settings = get_settings()

    # Martin supports function sources for filtered queries.
    # For table sources, we pass filter as query params.
    # Martin v0.14+ supports ?filter= parameter for table sources.
    # Use organization_id filter for multi-tenant isolation.
    url = (
        f"{settings.martin_tile_url}/parcel_cache/{z}/{x}/{y}"
    )

    try:
        response = await http_client.get(
            url,
            headers={"Accept": "application/vnd.mapbox-vector-tile"},
            timeout=10.0,
        )

        if response.status_code == 204:
            # No data for this tile
            return None

        response.raise_for_status()
        return response.content

    except httpx.HTTPError:
        return None
```

NOTE on Martin filtering: Martin table source auto-discovery serves the full table. For proper multi-tenant isolation, we have two options:
1. Use Martin function source with a SQL function that takes organization_id as parameter
2. Use PostGIS ST_AsMVT directly in the proxy (bypass Martin)

For MVP, option 2 is simpler. Create a `generate_mvt_tile` function that queries parcel_cache directly using PostGIS ST_AsMVT:

```python
async def generate_mvt_tile(
    z: int,
    x: int,
    y: int,
    organization_id: uuid.UUID,
    scan_id: uuid.UUID,
    db: AsyncSession,
) -> bytes | None:
    """Generate MVT tile directly from PostGIS with tenant filtering.

    Uses ST_AsMVT + ST_AsMVTGeom for server-side tile generation,
    filtered by organization_id for multi-tenant isolation.
    Bypasses Martin for security -- no external service has full table access.
    """
    # Calculate tile bounds (Web Mercator EPSG:3857)
    # Tile to bbox conversion: standard slippy map formula
    from math import pi, atan, sinh

    n = 2 ** z
    lon_min = x / n * 360 - 180
    lon_max = (x + 1) / n * 360 - 180
    lat_min_rad = atan(sinh(pi * (1 - 2 * (y + 1) / n)))
    lat_max_rad = atan(sinh(pi * (1 - 2 * y / n)))
    lat_min = lat_min_rad * 180 / pi
    lat_max = lat_max_rad * 180 / pi

    # Query using raw SQL for ST_AsMVT (SQLAlchemy doesn't wrap this well)
    query = text("""
        WITH
        bounds AS (
            SELECT ST_Transform(
                ST_MakeEnvelope(:lon_min, :lat_min, :lon_max, :lat_max, 4326),
                28992
            ) AS geom
        ),
        mvt_data AS (
            SELECT
                ST_AsMVTGeom(
                    pc.geometry,
                    bounds.geom,
                    4096, 256, true
                ) AS geom,
                pc.parcel_id,
                pc.address,
                pc.area_m2,
                pc.has_pand,
                sr.score,
                sr.flags->>'category' as score_category
            FROM parcel_cache pc
            JOIN scan_results sr ON sr.parcel_id = pc.id
            JOIN bounds ON ST_Intersects(pc.geometry, bounds.geom)
            WHERE pc.organization_id = :org_id
            AND sr.scan_id = :scan_id
            AND sr.organization_id = :org_id
        )
        SELECT ST_AsMVT(mvt_data, 'parcel_scores', 4096, 'geom')
        FROM mvt_data
    """)

    result = await db.execute(query, {
        "lon_min": lon_min,
        "lat_min": lat_min,
        "lon_max": lon_max,
        "lat_max": lat_max,
        "org_id": str(organization_id),
        "scan_id": str(scan_id),
    })

    row = result.scalar()
    if not row or len(row) == 0:
        return None
    return bytes(row)
```

Import `from sqlalchemy import text` and `from sqlalchemy.ext.asyncio import AsyncSession`. This approach:
- Filters by organization_id (multi-tenant safe)
- Filters by scan_id (shows only results from selected scan)
- Joins scan_results to get score data
- Uses ST_AsMVTGeom for proper tile coordinate transformation
- Returns MVT binary directly -- no Martin needed!

This is actually BETTER than using Martin because:
1. No external service to manage
2. Built-in multi-tenant filtering via SQL WHERE clause
3. No risk of data leakage
4. Score data included via JOIN (Martin would only serve parcel_cache columns)

So: Remove Martin from docker-compose.yml (not needed). Keep `tile_proxy.py` with the `generate_mvt_tile` function only.

But MapLibre makes tile requests via the `fetch` API internally. To add auth headers to MapLibre tile requests, use MapLibre's `transformRequest` option on the map or set `fetchOptions` on the source.
