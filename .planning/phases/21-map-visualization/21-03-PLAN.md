**PDOK Vector Tile URL:**
The PDOK Kadaster OGC API Tiles endpoint: `https://api.pdok.nl/kadaster/kadastralekaart/ogc/v1/tiles/NetherlandsRDNewQuad/{z}/{y}/{x}?f=mvt`

IMPORTANT: PDOK uses `NetherlandsRDNewQuad` as the tile matrix set for Dutch cadastral data. The source-layer name in the MVT is likely `perceel` or `Perceel`. Since this needs validation (Open Question #1 from research), use a constant `PDOK_PARCEL_SOURCE_LAYER = 'perceel'` that can be updated after testing.

**Alternative approach (more reliable):** If the OGC API Tiles endpoint proves difficult (Dutch tile matrix set vs WebMercator), fall back to the same WMS URL but as a `type: 'raster'` source with `tileSize: 256`. However, attempt the vector approach first.

**Actually, safer approach:** Looking at the research, the PDOK vector tile URL pattern needs validation. Use a pragmatic two-layer approach:
1. Keep the existing WMS raster parcel layer (ParcelBoundariesLayer.tsx) as-is for background parcel boundaries
2. Create ParcelVectorTileLayer.tsx that renders parcel data from a configurable vector tile source (used for Martin score tiles in 21-04)

So refocus this module:

3. `setParcelVectorTileVisibility(map: maplibregl.Map, visible: boolean): void` -- Toggle both layers
