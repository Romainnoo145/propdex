<objective>
Build the DSO Spatial Plans API client and zoning aggregation service. The client queries the DSO Ruimtelijke Plannen API v4 using POST with GeoJSON bodies for spatial lookups, then extracts bestemmingsvlakken and bouwvlakken. The aggregator performs spatial intersection with shapely to filter relevant zones, extracts permitted functions and building dimensions, and falls back to legacy Ruimtelijkeplannen.nl when DSO returns empty results.

Purpose: This is the core zoning intelligence -- the "headline data" for real estate developers (permitted function + building dimensions per user decision). Without this, the report has no bestemmingsplan summary.

Output: DSOSpatialPlansClient class and fetch_zoning_data aggregation function returning ZoningData.
</objective>

Create `backend/app/government_apis/dso_spatial_plans.py` following the established API client pattern (see bag_api.py, pdok_cadastral.py).

**Class: `DSOSpatialPlansClient`**

Constructor: `__init__(self, api_key: str = "")` — accept optional API key. If empty string, omit auth header (DSO may work without key for read-only queries, per research open question).

Properties:
- `_headers(self) -> dict[str, str]`: Return headers including:
  - `"Content-Type": "application/json"`
  - `"Content-Crs": "EPSG:28992"` (input coordinate system)
  - `"Accept-Crs": "EPSG:28992"` (output coordinate system)
  - If api_key is not empty: `"X-Api-Key": self.api_key` (most common Dutch API auth header pattern, same as BAG)

BASE_URL: `"https://ruimte.omgevingswet.overheid.nl/ruimtelijke-plannen/api/opvragen/v4"`

Methods:

1. `async def find_plans_at_location(self, x: float, y: float, client: httpx.AsyncClient) -> list[dict]`:
   - POST to `{BASE_URL}/plannen/_zoek` with GeoJSON Point body: `{"type": "Point", "coordinates": [x, y]}`
   - Use `self._headers` (which include Content-Crs and Accept-Crs)
   - Set timeout=30.0
   - Parse HAL+JSON: `data.get("_embedded", {}).get("plannen", [])`
   - Handle pagination: check `data.get("_links", {}).get("next", {}).get("href")`. If next link exists, fetch up to 5 pages (safety limit). Accumulate all plans.
   - Wrap httpx.TimeoutException as APITimeoutError
   - Log: plan count found
   - Return list of plan dicts

2. `async def get_bestemmingsvlakken(self, plan_id: str, client: httpx.AsyncClient) -> list[dict]`:
   - GET `{BASE_URL}/plannen/{plan_id}/bestemmingsvlakken`
   - params: `{"expand": "geometrie", "pageSize": 100}` (request geometry inline, larger page)
   - Use self._headers (minus Content-Type since this is GET)
   - Parse HAL+JSON: `data.get("_embedded", {}).get("bestemmingsvlakken", [])`
   - Handle pagination same as above (up to 5 pages)
   - Return list of bestemmingsvlak dicts

3. `async def get_bouwvlakken(self, plan_id: str, client: httpx.AsyncClient) -> list[dict]`:
   - GET `{BASE_URL}/plannen/{plan_id}/bouwvlakken`
   - params: `{"expand": "geometrie", "pageSize": 100}`
   - Parse HAL+JSON: `data.get("_embedded", {}).get("bouwvlakken", [])`
   - Handle pagination (up to 5 pages)
   - Return list of bouwvlak dicts

4. `async def get_maatvoeringen(self, plan_id: str, client: httpx.AsyncClient) -> list[dict]`:
   - GET `{BASE_URL}/plannen/{plan_id}/maatvoeringen`
   - params: `{"expand": "geometrie", "pageSize": 100}`
   - Parse HAL+JSON: `data.get("_embedded", {}).get("maatvoeringen", [])`
   - Handle pagination (up to 5 pages)
   - Return list of maatvoering dicts (contains building dimension values)

Use consistent error handling pattern:
```python
try:
    response = await client.post/get(...)
    data = handle_api_response(response, source="dso-spatial-plans")
except httpx.TimeoutException as e:
    raise APITimeoutError("dso-spatial-plans", "Request timed out") from e
except httpx.HTTPError as e:
    raise GovernmentAPIError("dso-spatial-plans", f"HTTP error: {str(e)}") from e
```

Add module-level logger: `logger = logging.getLogger(__name__)`

Create module-level singleton at bottom: `_dso_client: DSOSpatialPlansClient | None = None` and a getter function:
```python
def get_dso_client() -> DSOSpatialPlansClient:
    global _dso_client
    if _dso_client is None:
        _dso_client = DSOSpatialPlansClient(api_key=settings.DSO_API_KEY)
    return _dso_client
```

Create `backend/app/services/zoning_aggregator.py` — the service that orchestrates zoning data collection and extraction.

**Imports:** shapely.geometry (Point, shape), DSOSpatialPlansClient/get_dso_client, cache_manager, ZoningData/ZoningPlan/ZoningRule/BuildingDimensions schemas, handle_api_response, GovernmentAPIError, logging, httpx, uuid, AsyncSession.

**Helper function: `_find_containing_features(property_point: Point, features: list[dict], geometry_key: str = "geometrie") -> list[dict]`**
- For each feature, extract geometry from `feature.get(geometry_key)` or `feature.get("_embedded", {}).get("geometrie")` (DSO may nest under _embedded)
- Use `shape(geometry_data)` to convert GeoJSON to shapely geometry
- Check `zone_geom.contains(property_point)` for point-in-polygon
- Also try `zone_geom.intersects(property_point)` as fallback (handles edge cases where point is on boundary)
- Log and skip features with invalid geometry (try/except around shape())
- Return list of features that contain/intersect the point

**Helper function: `_extract_building_dimensions(maatvoeringen: list[dict], property_point: Point) -> BuildingDimensions`**
- Filter maatvoeringen to those containing property_point (reuse _find_containing_features)
- Look for common Dutch maatvoering fields in the feature properties:
  - `"maximale bouwhoogte"` or similar -> max_bouwhoogte
  - `"maximale goothoogte"` -> max_goothoogte
  - `"maximum bebouwingspercentage"` -> max_bebouwingspercentage
  - `"maximum floor area ratio"` or `"floor space index"` -> max_floor_area_ratio
- The exact field names may vary per plan — check for common patterns in `naam` or `omschrijving` fields
- Parse numeric values from string representations (they may be "10 m" or just "10")
- Return BuildingDimensions with whatever was found (None for unfound fields)

**Helper function: `_filter_and_sort_plans(plans: list[dict]) -> list[dict]`**
- Filter to plans with `status` containing "vastgesteld" (finalized) — case-insensitive check
- If no vastgesteld plans found, include "ontwerp" (draft) plans as backup but log a warning
- Sort by `datum` descending (newest first) — handle missing datum gracefully
- Return filtered/sorted list

**Main function: `async def fetch_zoning_data(x: float, y: float, client: httpx.AsyncClient, organization_id: uuid.UUID, session: AsyncSession, force_refresh: bool = False) -> ZoningData | None`**

Flow:
1. Create cache_key: `f"dso:zoning:{x}:{y}"`
2. Define inner async fetch function for cache_manager:
   ```python
   async def _fetch():
       dso = get_dso_client()
       plans = await dso.find_plans_at_location(x, y, client)
       # ... process plans and return raw dict for caching
   ```
3. Use `get_cached_or_fetch(cache_key, "dso", organization_id, _fetch, session, force_refresh=force_refresh)`
4. The cached data should be the raw API response dict. After retrieving from cache, process into ZoningData:

Processing logic (operates on cached or fresh data):
1. Filter and sort plans using `_filter_and_sort_plans()`
2. If no plans found from DSO, set `fallback_used = True` and log warning. For MVP, return ZoningData with empty plans and a data_gap noting "Geen bestemmingsplan gevonden via DSO API" (actual WFS fallback implementation deferred — the client structure supports adding it later, but the WFS parsing is complex enough to warrant its own task if needed)
3. For each plan (process the top 3 most recent to avoid context explosion):
   a. Fetch bestemmingsvlakken via `dso.get_bestemmingsvlakken(plan_id, client)`
   b. Use `_find_containing_features()` to filter to zones containing property point
   c. Fetch maatvoeringen via `dso.get_maatvoeringen(plan_id, client)` for building dimensions
   d. Use `_extract_building_dimensions()` for dimension data
   e. Fetch bouwvlakken via `dso.get_bouwvlakken(plan_id, client)` for additional building rules
   f. Build ZoningRule for each relevant zone with bestemming name, omschrijving, building_dimensions, geometry
   g. Build ZoningPlan with plan metadata and rules list

4. Determine `primary_bestemming`: Take the bestemming name from the first rule of the newest vastgesteld plan
5. Determine consolidated `building_dimensions`: From primary plan's first rule's dimensions
6. Build `data_gaps` list per user decision ("Not specified in plan"):
   - If no building_dimensions found: "Bouwregels niet beschikbaar in bestemmingsplan"
   - If max_hoogte is None: "Maximale bouwhoogte niet gespecificeerd"
   - If max_bebouwingspercentage is None: "Maximaal bebouwingspercentage niet gespecificeerd"
   - If max_floor_area_ratio is None: "Floor area ratio niet gespecificeerd"
   Use Dutch for data gap messages.

7. Return ZoningData with all assembled data

**Error handling:**
- Wrap entire function in try/except
- GovernmentAPIError: log warning, return ZoningData with empty plans and data_gap explaining error
- Exception: log error, return None (let aggregator handle it as partial failure)

Add module-level logger: `logger = logging.getLogger(__name__)`
