<task type="auto">
  <name>Task 2: Create zoning, monument, and extended property schemas</name>
  <files>backend/app/schemas/zoning.py, backend/app/schemas/monument.py, backend/app/schemas/property.py</files>
  <action>
1. **Create `backend/app/schemas/zoning.py`** with these Pydantic BaseModel schemas:

   - `BuildingDimensions(BaseModel)`:
     - `max_hoogte: float | None` (max building height in meters)
     - `max_bebouwingspercentage: float | None` (max coverage percentage, 0-100)
     - `max_floor_area_ratio: float | None` (floor space index / FSI)
     - `max_goothoogte: float | None` (max gutter height in meters)
     - `max_bouwhoogte: float | None` (max construction height in meters)
     - Each field has `default=None` with descriptive Field labels
     - Add a computed property `has_any_data` returning True if any field is not None

   - `ZoningRule(BaseModel)`:
     - `bestemming: str` (permitted function name, e.g., "Wonen", "Gemengd")
     - `omschrijving: str | None = None` (description of permitted uses)
     - `building_dimensions: BuildingDimensions | None = None`
     - `geometry: dict | None = None` (GeoJSON for map rendering, exclude from default serialization using `Field(exclude=True)` -- actually keep it, frontend needs it for map)

   - `ZoningPlan(BaseModel)`:
     - `plan_id: str` (DSO plan identifier)
     - `plan_naam: str` (plan name)
     - `plan_type: str | None = None` (e.g., "bestemmingsplan", "omgevingsplan")
     - `plan_status: str | None = None` (e.g., "vastgesteld", "ontwerp")
     - `plan_datum: str | None = None` (plan date ISO format)
     - `rules: list[ZoningRule]` (zoning rules extracted for property location)

   - `ZoningData(BaseModel)`:
     - `plans: list[ZoningPlan]` (may be multiple overlapping plans)
     - `primary_bestemming: str | None = None` (most relevant permitted function from newest vastgesteld plan)
     - `building_dimensions: BuildingDimensions | None = None` (consolidated from primary plan)
     - `data_gaps: list[str] = Field(default_factory=list)` (explicitly mark missing fields per user decision, e.g., ["Parking requirements not specified in plan", "Floor area ratio not available"])
     - `source: str = "DSO Ruimtelijke Plannen API v4"` (or "Ruimtelijkeplannen.nl WFS" if fallback used)
     - `fallback_used: bool = False` (True if DSO returned nothing and legacy API was used)

2. **Create `backend/app/schemas/monument.py`** with:

   - `MonumentSourceResult(BaseModel)`:
     - `source: str` (one of "RCE", "BAG", "Kadaster")
     - `is_monument: bool | None = None` (True/False/None if source couldn't determine)
     - `monument_type: str | None = None` (e.g., "rijksmonument", "gemeentelijk monument", None)
     - `monument_nummer: str | None = None` (rijksmonument number if applicable)
     - `monument_naam: str | None = None` (monument name/description from RCE)
     - `cached_at: str | None = None` (ISO timestamp)
     - `age_seconds: int | None = None`
     - `error: str | None = None` (if source lookup failed, explain why)

   - `MonumentStatus(BaseModel)`:
     - `sources: list[MonumentSourceResult]` (results from each checked source)
     - `has_conflict: bool = False` (True if sources disagree on monument status)
     - `conflict_note: str | None = None` (Dutch explanation of discrepancy, e.g., "RCE registreert dit als rijksmonument, BAG geeft geen monumentstatus aan")
     - `consensus_status: str | None = None` (overall status if sources agree: "rijksmonument", "gemeentelijk_monument", "geen_monument", None if conflict)
     - `restrictions_summary: list[str] = Field(default_factory=list)` (plain language heritage restrictions, e.g., ["Wijzigingen aan de gevel vereisen een monumentenvergunning", "Sloop is niet toegestaan zonder ontheffing"])
     - `is_monument: bool` (computed: True if ANY source says it's a monument -- use a @model_validator or property)

3. **Extend `backend/app/schemas/property.py`** - Add new schemas and extend existing DataSourceInfo:

   - **Add confidence field to existing `DataSourceInfo(BaseModel)`**:
     - `confidence: Literal["HIGH", "MEDIUM", "LOW"] | None = Field(default=None, description="Data quality confidence: HIGH=authoritative API data, MEDIUM=parsed structured data, LOW=AI-extracted data")`
     - For Phase 3: All API sources use "HIGH" (authoritative government APIs)
     - Phase 4 will introduce "MEDIUM"/"LOW" for AI-parsed zoning/monument data
     - This field addresses PROP-06 requirement for confidence indicators

   - `SectionSourceInfo(BaseModel)`:
     - `section: str` (e.g., "address", "building", "cadastral", "zoning", "monuments")
     - `sources: list[DataSourceInfo]` (may have multiple for monuments)
     - `cached_at: str | None = None`
     - `age_seconds: int | None = None`
     - Add a computed property `freshness_display_nl` that returns Dutch relative time:
       - < 60s: "Zojuist bijgewerkt"
       - < 3600s: "{minutes} minuten geleden"
       - < 86400s: "{uur} uur geleden"
       - >= 86400s: "{dagen} dagen geleden"
       - None if no cached_at

   - `MapData(BaseModel)`:
     - `center_rd: list[float] | None = None` (EPSG:28992 [x, y] center point)
     - `center_wgs84: list[float] | None = None` ([lon, lat] for frontend map libraries)
     - `property_geometry: dict | None = None` (building GeoJSON polygon)
     - `parcel_geometries: list[dict] = Field(default_factory=list)` (cadastral parcel GeoJSON)
     - `zoning_geometries: list[dict] = Field(default_factory=list)` (bestemmingsvlak GeoJSON polygons)
     - `tile_url: str = "https://service.pdok.nl/brt/achtergrondkaart/wmts/v2_0/standaard/EPSG:3857/{z}/{x}/{y}.png"` (PDOK BRT tile URL template per user decision)

   - `PropertyReportResponse(BaseModel)`:
     - Keep ALL existing fields from PropertyLookupResponse (address, building, cadastral_parcels, data_sources, completeness_score, errors, resolved_at)
     - Add: `zoning: ZoningData | None = None`
     - Add: `monuments: MonumentStatus | None = None`
     - Add: `map_data: MapData | None = None`
     - Add: `section_sources: list[SectionSourceInfo] = Field(default_factory=list)` (section-level attribution per user decision)
     - Import ZoningData from app.schemas.zoning
     - Import MonumentStatus from app.schemas.monument
     - Do NOT modify existing PropertyLookupResponse — create PropertyReportResponse as a NEW model that extends the data contract. The existing PropertyLookupResponse stays for backward compatibility.

   Use `from __future__ import annotations` at top of all new schema files for forward references.
   Follow existing Pydantic patterns: BaseModel, Field with description, type | None for optional fields.
  </action>
