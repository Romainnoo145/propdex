**2. Add Three-Step Progress Stepper (FB-05)**

Define the scan steps array inside the component (not a separate file — keep stepper scan-specific per research recommendation):
```tsx
const SCAN_STEPS = [
  { id: 'fetching_parcels', label: 'Kadaster ophalen', sublabel: 'Percelen van Kadaster WFS' },
  { id: 'cross_referencing_bag', label: 'BAG controleren', sublabel: 'Gebouwen cross-refereren' },
  { id: 'querying_bestemmingen', label: 'Bestemmingen', sublabel: 'DSO API opvragen' },
] as const
```

Create a helper to determine step state:
```tsx
function getStepState(stepId: string, currentPhase: string | null, isCompleted: boolean, isFailed: boolean): 'pending' | 'active' | 'completed'
```
Logic:
- If `isCompleted` (scan completed): all steps are 'completed'
- If `isFailed` (scan failed): steps up to current phase are 'completed', current is 'active' (failed at this step), rest are 'pending'
- If `currentPhase === null` (queued): all steps are 'pending'
- Otherwise: steps before `currentPhase` in the SCAN_STEPS array are 'completed', the one matching `currentPhase` is 'active', the rest are 'pending'

Render the stepper as a horizontal row of three step items, each showing:
- A numbered circle (1, 2, 3):
  - `completed`: bg-success text-grey-950, show checkmark icon instead of number
  - `active`: bg-amber-accent text-grey-950, show number
  - `pending`: bg-grey-800 text-grey-400, show number
- Step label below the circle: `text-xs`, color matching the step state
- Connecting line between circles: `bg-success` for completed connections, `bg-grey-800` for pending

Below the stepper, keep the existing progress bar (but with new tokens) and parcel counter.
