  <action>
    Create `rate_limiter.py` in `backend/app/government_apis/` with:

    1. `APIRateLimiter` class:
       - Constructor takes `max_concurrent: int` (semaphore limit) and `max_per_hour: int` (token bucket capacity)
       - Uses `asyncio.Semaphore` for concurrency control
       - Uses `aiolimiter.AsyncLimiter` for time-based rate limiting (max_rate=max_per_hour, time_period=3600)
       - Implements `__aenter__` and `__aexit__` for async context manager pattern:
         - `__aenter__`: acquire semaphore, then acquire token bucket token
         - `__aexit__`: release semaphore (token bucket releases automatically)
       - Add `enabled: bool` attribute (default True) so tests can disable rate limiting

    2. Module-level singleton instances:
       - `bag_wfs_limiter = APIRateLimiter(max_concurrent=5, max_per_hour=1000)` -- PDOK is public, generous limits
       - `sru_limiter = APIRateLimiter(max_concurrent=3, max_per_hour=500)` -- SRU is less tolerant
       - `brk_limiter = APIRateLimiter(max_concurrent=2, max_per_hour=200)` -- BRK is paid, conservative

    3. Follow existing codebase patterns:
       - Module docstring
       - Logging via `logging.getLogger(__name__)`
       - Type hints on all parameters and return types
       - Keep under 100 lines

    Key design: When `enabled=False`, `__aenter__`/`__aexit__` should be no-ops (skip acquire/release) to allow fast tests without rate limiting delays.
  </action>

  </verify>
