**2. Add internal function `fetchGetFeatureInfo(map, lngLat)`:**

Constructs a WMS GetFeatureInfo URL with these parameters:
- `service=WMS`, `version=1.3.0`, `request=GetFeatureInfo`
- `layers=enkelbestemming`, `query_layers=enkelbestemming`
- `info_format=application/json` (try JSON first -- PDOK typically supports this)
- `feature_count=1`
- `crs=EPSG:4326` for GetFeatureInfo (NOT EPSG:3857 -- bbox and I/J must match CRS)
- `bbox` from `map.getBounds()` formatted as `west,south,east,north`
- `width` and `height` from `map.getContainer().getBoundingClientRect()` (floored to int)
- `i` and `j` from `map.project(lngLat)` (floored to int) -- pixel coordinates

**CRITICAL CRS NOTE:** For WMS 1.3.0 with CRS=EPSG:4326, the bbox axis order is lat,lon (y,x) not lon,lat. So bbox should be `south,west,north,east`. This is a known WMS 1.3.0 gotcha. However, PDOK may not follow the axis order strictly. The implementation should try EPSG:4326 with standard lon,lat order first. If GetFeatureInfo returns empty, the SUMMARY should document this and suggest trying axis-swapped bbox or EPSG:3857 as fallback.

Cancel any in-flight request using AbortController before starting a new one.

Fetch with `signal: abortController.signal`. On success, parse the JSON response. The PDOK GetFeatureInfo response is expected to be a GeoJSON FeatureCollection. Extract from `features[0].properties`:
- `plannaam` or `naam` -> `planNaam`
- `bestemmingshoofdgroep` or `bestemming` -> `bestemmingType`
- `planstatus` -> `planStatus`
- `verwijzingNaarExternPlanInfo` or `planurl` -> `planLink`

Property names are uncertain (research open question #1). Use defensive access with fallbacks:
```typescript
const props = feature.properties || {}
const planNaam = props.plannaam ?? props.naam ?? props.planNaam ?? 'Onbekend plan'
const bestemmingType = props.bestemmingshoofdgroep ?? props.bestemming ?? props.type ?? 'Onbekend'
```

Return `ZoneFeatureInfo | null` (import from `@/lib/types/bestemmingsplan`).

**3. Add exported function `setupBestemmingsplanClickHandler(map, onZoneClick, onZoneLoading)`:**

Parameters:
- `map: maplibregl.Map`
- `onZoneClick: (info: ZoneFeatureInfo, lngLat: [number, number]) => void`
- `onZoneLoading: (loading: boolean) => void`

Registers a click handler on the map (NOT on the layer -- raster layers don't support layer-specific click events in MapLibre). The click handler:
1. Check if bestemmingsplan-layer exists and is visible. If not, return early.
2. Call `onZoneLoading(true)`
3. Call `fetchGetFeatureInfo(map, e.lngLat)`
4. On success (non-null result): call `onZoneClick(result, [e.lngLat.lng, e.lngLat.lat])`
5. Call `onZoneLoading(false)` in finally block

Also register mouseenter/mouseleave on the map to change cursor to 'pointer' when bestemmingsplan layer is visible (check visibility state).

Return a cleanup function that removes the event handlers (for useEffect cleanup).
