**Test class: TestReportIsolation** (4 tests)

- `test_get_cross_org_returns_404`: Org A saves a report. Call `service.get_report(report_a.id, org_b_id, test_db)`. Assert raises HTTPException with status_code 404. This proves org B gets 404 (not 403) preventing resource enumeration.

- `test_list_cross_org_returns_empty`: Org A saves 2 reports. Call `service.list_reports(organization_id=org_b_id, ...)`. Assert total==0 and len(reports)==0.

- `test_delete_cross_org_returns_404`: Org A saves a report. Call `service.soft_delete_report(report_a.id, org_b_id, test_db)`. Assert raises HTTPException with status_code 404. Then verify org A's report still exists (not deleted).

- `test_distinct_cities_cross_org_isolated`: Org A saves reports in Amsterdam and Rotterdam. Org B saves report in Utrecht. Call `service.get_distinct_cities(org_a_id, test_db)`. Assert ["Amsterdam", "Rotterdam"]. Call `service.get_distinct_cities(org_b_id, test_db)`. Assert ["Utrecht"].

**Test class: TestSoftDeleteIsolation** (2 tests)

- `test_deleted_report_invisible_to_own_org_list`: Org A saves report, soft-deletes it. List reports for org A. Assert total==0.

- `test_deleted_report_invisible_to_other_org_get`: Org A saves report, soft-deletes it. Call `service.get_report(report_a.id, org_b_id, test_db)`. Assert raises HTTPException 404 (not leaked via cross-org access even when deleted).

**Test class: TestCacheIsolation** (1 test)

- `test_same_cache_key_different_orgs_independent`: Use `get_cached_or_fetch` with same cache_key="bag:test:isolation" for org_a and org_b with different fetch_fn return values (AsyncMock). Assert both fetch functions called (not shared). Assert result_a.data != result_b.data. This is a focused retest confirming cache isolation holds alongside report isolation.

**Test class: TestAPIEndpointIsolation** (2 tests)

These tests use async_client fixture with JWT tokens to verify API-level isolation.

- `test_api_get_report_cross_org_returns_404`: Use `two_orgs_with_users` fixture. Org A saves report via service layer. Create JWT for org B: `token_b = create_access_token(str(user_b.id), str(org_b.organization_id))`. Send `GET /api/reports/{report_a.id}` with `headers={"Authorization": f"Bearer {token_b}"}`. Assert status_code == 404.

- `test_api_list_reports_cross_org_empty`: Org A saves 2 reports via service layer. Create JWT for org B. Send `GET /api/reports` with org B's token. Assert status_code == 200, response.json()["total"] == 0.

For API tests, import `from app.auth.jwt import create_access_token`. For cache tests, import `from app.services.cache_manager import get_cached_or_fetch` and `from unittest.mock import AsyncMock`.

IMPORTANT: For API endpoint tests, the `get_current_organization_id` dependency reads `request.state.organization_id` which is set by middleware from the JWT. The async_client fixture already overrides get_db. The middleware must parse the JWT and set organization_id on request.state. If this doesn't happen automatically via the app middleware stack in tests, the API tests may need to be adapted. The service-layer tests (TestReportIsolation, TestSoftDeleteIsolation) are the critical isolation proof; API tests are supplementary confirmation.
