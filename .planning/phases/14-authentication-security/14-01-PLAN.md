  <action>
1. In `backend/app/auth/schemas.py`, add a new schema `CookieTokenResponse` that returns ONLY `access_token` and `token_type` (no `refresh_token` field). Keep the existing `TokenResponse` for backwards compatibility with tests.

2. In `backend/app/auth/router.py`, add a helper function `_set_refresh_cookie(response: Response, refresh_token: str)` that sets the cookie:
   ```python
   def _set_refresh_cookie(response: Response, refresh_token: str) -> None:
       response.set_cookie(
           key="refresh_token",
           value=refresh_token,
           httponly=True,
           secure=False,  # Allow HTTP in development (localhost)
           samesite="lax",
           max_age=settings.REFRESH_TOKEN_EXPIRE_DAYS * 24 * 60 * 60,
           path="/api/auth",  # Only send cookie to auth endpoints
       )
   ```
   Note: `secure=False` for development. In production, this should be True. A future deployment plan will address this. `path="/api/auth"` limits cookie scope for security.

3. Add a helper `_clear_refresh_cookie(response: Response)` that deletes the cookie:
   ```python
   def _clear_refresh_cookie(response: Response) -> None:
       response.delete_cookie(key="refresh_token", path="/api/auth")
   ```

4. Add `from fastapi import Response` to imports (it may already be partially imported).

The endpoint should work gracefully if no cookie is present (return success).
