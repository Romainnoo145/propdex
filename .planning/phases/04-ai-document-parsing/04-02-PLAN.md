  **1. Create app/ai/prompts.py:**
  Define the Dutch bestemmingsplan parsing prompt as a constant. The prompt instructs Claude to:
  - Extract ALL zoning rules (artikelen) relevant for property developers
  - Assign per-rule confidence scores (HIGH/MEDIUM/LOW) based on text clarity
  - Generate Dutch disclaimers ONLY for LOW-confidence items
  - Include article references for source verification
  - Focus on: permitted/forbidden uses, building dimensions, parking norms, environmental restrictions, special conditions
  - Provide a brief Dutch summary (samenvatting) of key findings

  ```python
  BESTEMMINGSPLAN_PARSING_PROMPT = """
  Je bent een expert in het analyseren van Nederlandse bestemmingsplannen voor vastgoedontwikkelaars.
  Analyseer dit bestemmingsplan-PDF en extraheer alle relevante regels.

  **Te extraheren per regel:**
  1. Artikelverwijzing (exacte verwijzing, bijv. "Artikel 3.1.2 Wonen")
  2. Bestemming (bijv. "Woongebied", "Gemengd gebied", "Centrum")
  3. Toegestane gebruiken (lijst, bijv. ["wonen", "kantoor aan huis", "bed & breakfast"])
  4. Verboden gebruiken (lijst, bijv. ["bedrijfsmatige activiteiten", "horeca", "detailhandel"])
  5. Bouwregels: maximale bouwhoogte (m), goothoogte (m), bebouwingspercentage (%), oppervlakte (m2), inhoud (m3)
  6. Parkeereis (bijv. "2 parkeerplaatsen per woning" of "conform CROW-normen")
  7. Milieurestrictions (bijv. geluidszones, geurcontouren, bodemkwaliteitseisen)
  8. Bijzondere voorwaarden (wijzigingsbevoegdheden, afwijkingsregels, uitzonderingen, overgangsrecht)

  **Vertrouwensscore per regel:**
  - HIGH: Duidelijke, eenduidige regeltekst zonder verwijzingen naar externe bronnen
  - MEDIUM: Regels met verwijzingen naar andere artikelen, voorwaardelijke bepalingen, of samengestelde eisen
  - LOW: Onduidelijke formuleringen, tegenstrijdigheden, ontbrekende informatie, of complexe ketenbepaling

  **Disclaimers (alleen voor LOW-confidence items):**
  Genereer een Nederlandse waarschuwing per LOW-confidence item, bijvoorbeeld:
  - "Artikel {X} bevat onduidelijke formuleringen — raadpleeg notaris voor interpretatie"
  - "Mogelijke tegenstrijdigheid tussen artikel {X} en {Y} — verificatie bij gemeente vereist"
  - "Verwijzing naar extern beleidsdocument niet beschikbaar — controleer actuele status"

  **Samenvatting:**
  Schrijf een beknopte Nederlandse samenvatting (2-4 zinnen) van de belangrijkste bevindingen:
  - Primaire bestemming en hoofdgebruik
  - Belangrijkste bouwmogelijkheden of -beperkingen
  - Eventuele bijzonderheden of aandachtspunten

  **Instructies:**
  - Extraheer ALLE regels, ook die met LOW confidence — het weglaten van regels is erger dan onzekerheid
  - Behoud exacte artikelverwijzingen zodat ontwikkelaars de bron kunnen controleren
  - Bij twijfel over een waarde, zet confidence op LOW en genereer een disclaimer
  - Focus op ontwikkelingsrelevante informatie (bouwmogelijkheden, restricties, uitzonderingen)
  - Als het plan-IDN (NL.IMRO-nummer) in het document staat, neem dit over in plan_idn
  """
  ```

  **2. Create app/ai/claude_client.py:**
  Async wrapper around the Anthropic SDK for PDF parsing with structured outputs.

  Key implementation details:
  - Use `anthropic.AsyncAnthropic` for async compatibility (the project is fully async)
  - Use the `messages.create()` method with a system prompt and user message containing the PDF document
  - Send PDF as base64-encoded document block with `cache_control: {"type": "ephemeral"}` for prompt caching (90% cost reduction on repeated plans)
  - Use `response_model` or `output_format` parameter with `BestemmingsplanParsed` Pydantic model for guaranteed structured JSON output
  - Model: `"claude-sonnet-4-5"` (good balance of cost and quality for document parsing)
  - `max_tokens`: 16000 (sufficient for complex bestemmingsplannen)
  - Handle Anthropic API errors gracefully: catch `anthropic.APIError`, `anthropic.RateLimitError`, `anthropic.APIConnectionError`
  - On any error, raise a custom `AIParsingError` (define in same file) with descriptive message
  - Do NOT auto-retry per user decision — immediate fail with error

  ```python

          """Parse bestemmingsplan PDF with Claude and return structured output."""

  ```

  NOTE on structured outputs: Check the anthropic SDK API. The recommended approach for Pydantic-based structured output is `client.messages.create()` with a system prompt that includes the JSON schema, and then parse the text response. The executor should check the SDK version and use the best available method.

  <action>
  Create `app/services/pdf_downloader.py` — service for downloading bestemmingsplan PDFs from Ruimtelijkeplannen.nl and storing them in PostgreSQL BYTEA.

  **Key functions:**

  **1. `validate_imro_identifier(plan_idn: str) -> bool`:**
  Validate IMRO format using regex: `^NL\.IMRO\.\d{4}\..+-\w+$`
  Note: The regex from research (`^NL\.IMRO\.\d{4}\.[A-Z0-9]{1,18}-[A-Z0-9]{1,4}$`) is too strict — real IMRO identifiers use mixed case and longer names. Use a more permissive pattern but still validate the NL.IMRO prefix and basic structure.

  **2. `construct_pdf_url(plan_idn: str) -> str`:**
  Construct the download URL from the plan identifier. The Ruimtelijkeplannen.nl pattern needs runtime testing, but the likely format is:
  `f"https://www.ruimtelijkeplannen.nl/documents/{plan_idn}/d_{plan_idn}.pdf"`

  If that fails, an alternative is to query the DSO API for the plan's document links. Include both approaches:
  - Primary: Direct URL construction
  - Fallback: Log warning and return None (let caller handle with manual upload)

  **3. `download_and_store_pdf(plan_idn, organization_id, session, client) -> PDFDocument`:**
  Main function. Steps:
  1. Check if PDF already stored for this plan_idn + organization_id (SELECT from pdf_documents)
  2. If exists, return existing PDFDocument
  3. If not, validate IMRO identifier
  4. Construct URL and download with httpx client (timeout=60s for large files)
  5. Validate: PDF only (check content-type header or first bytes `%PDF`), max 100MB
  6. Store in PDFDocument model: file_data=bytes, file_size=len(bytes), source_url, is_user_uploaded=False
  7. session.add(), session.flush(), session.commit()
  8. Return PDFDocument

  On download failure (404, timeout, etc.), raise a `PDFDownloadError` (define in same file) with descriptive message.

  **4. `store_uploaded_pdf(plan_idn, pdf_data, organization_id, session) -> PDFDocument`:**
  Store a user-uploaded PDF. Steps:
  1. Validate PDF magic bytes (first 4 bytes should be `%PDF`)
  2. Validate size <= 100MB
  3. Validate IMRO identifier format
  4. Create PDFDocument with is_user_uploaded=True, source_url=None
  5. session.add(), session.flush(), session.commit()
  6. Return PDFDocument

  **5. `get_stored_pdf(plan_idn, organization_id, session) -> PDFDocument | None`:**
  Check if a PDF is already stored for this plan. Used by the parsing job to skip re-download.

  Follow existing patterns:
  - Use `from sqlalchemy import select` for queries
  - Use `datetime.utcnow()` for naive datetimes
  - Direct `db.add()/db.flush()/db.commit()` — NOT `async with db.begin()`
  - `httpx.AsyncClient` received as parameter (not created internally)
  - Log operations with `logging.getLogger(__name__)`
