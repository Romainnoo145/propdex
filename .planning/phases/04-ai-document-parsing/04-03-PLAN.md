  **2. Create app/jobs/pdf_parsing.py:**
  The core background job function. This runs inside the ARQ worker process, NOT inside FastAPI.

  ```python
  async def pdf_parsing_job(
      ctx: dict,
      plan_idn: str,
      organization_id: str,
      pdf_url: str | None = None,
  ) -> dict:
      """
      Background job: Download bestemmingsplan PDF, parse with Claude, store results.

      Runs in ARQ worker process. Job state tracked in Redis,
      parsed results stored in PostgreSQL CachedAPIResponse.

      Args:
          ctx: ARQ context (contains redis connection, etc.)
          plan_idn: IMRO plan identifier
          organization_id: Tenant UUID as string
          pdf_url: Optional explicit PDF URL (None = construct from plan_idn)

      Returns:
          dict with plan_idn and status for ARQ result storage
      """
  ```

  Implementation steps inside the job function:
  1. Create a new database session (the worker runs outside FastAPI, so must create its own session)
     - Import `async_sessionmaker` and create engine from settings.DATABASE_URL
     - Use a context-managed session
  2. Update ParsingJob status to "in_progress" (SELECT by plan_idn + organization_id, UPDATE status)
  3. Get or download PDF:
     - Call `get_stored_pdf(plan_idn, org_id, session)` first
     - If not stored, create an httpx.AsyncClient and call `download_and_store_pdf()`
     - If download fails, update ParsingJob status to "failed" with error_message, return error dict
  4. Parse with Claude:
     - Create `ClaudeClient(api_key=settings.ANTHROPIC_API_KEY)`
     - Call `client.parse_bestemmingsplan(pdf_doc.file_data, plan_idn)`
     - If parsing fails (AIParsingError), update ParsingJob to "failed", return error dict
  5. Store parsed results in cache:
     - Use the existing `CachedAPIResponse` model directly (not via cache_manager since we need to store dict)
     - Cache key: `f"ai_parsed:{plan_idn}"`
     - Source: `"ai_parsed"` (matches CACHE_TTL)
     - Data: `parsed_result.model_dump()` (Pydantic to dict)
     - Upsert pattern: check if exists, update or create
  6. Update ParsingJob status to "complete"
  7. Return `{"plan_idn": plan_idn, "status": "completed"}`

  IMPORTANT: The job function must handle its own database connection lifecycle since it runs in a separate worker process. Use the same DATABASE_URL from settings but create a new engine/session.

  IMPORTANT: Wrap entire job body in try/except to ensure ParsingJob status is always updated on failure. Never leave a job in "in_progress" state permanently.

  **3. Create app/jobs/worker.py:**
  ARQ worker configuration.

  ```python
  from arq.connections import RedisSettings
  from app.core.config import settings
  from app.jobs.pdf_parsing import pdf_parsing_job

  def get_redis_settings() -> RedisSettings:
      """Parse REDIS_URL into ARQ RedisSettings."""
      # Parse redis://host:port/db format
      from urllib.parse import urlparse
      parsed = urlparse(settings.REDIS_URL)
      return RedisSettings(
          host=parsed.hostname or "localhost",
          port=parsed.port or 6379,
          database=int(parsed.path.lstrip("/") or "0"),
          password=parsed.password,
      )

  class WorkerSettings:
      """ARQ worker configuration for PDF parsing jobs."""
      functions = [pdf_parsing_job]
      redis_settings = get_redis_settings()
      max_jobs = 5  # Max concurrent parsing jobs (limited by Claude API rate)
      job_timeout = 300  # 5 minutes for download + parse + store
      max_tries = 1  # No auto-retry per user decision
      health_check_interval = 30  # Seconds between health checks
  ```

  The worker runs via: `arq app.jobs.worker.WorkerSettings` from the backend directory.

  Create `app/services/plan_aggregator.py` — service that decides whether to return cached AI-parsed data, return an in-progress job reference, or enqueue a new parsing job.

  **Key functions:**

  **1. `get_or_parse_plan(plan_idn, organization_id, session, arq_pool) -> AIParsingSection`:**
  Main orchestration function. Returns an `AIParsingSection` schema (from ai/schemas.py) indicating the current state.

  Steps:
  1. **Cache check:** Query CachedAPIResponse for cache_key=`f"ai_parsed:{plan_idn}"`, organization_id=org_id
     - If found and not expired (age < TTL): return AIParsingSection(status="complete", parsed_plan=BestemmingsplanParsed(**cached.response_data))
  2. **Active job check:** Query ParsingJob for plan_idn + organization_id where status IN ("queued", "in_progress")
     - If found: return AIParsingSection(status=job.status, job_id=job.job_id)
  3. **Enqueue new job:**
     - Create ParsingJob record (job_id will be set after enqueue)
     - Enqueue via `arq_pool.enqueue_job("pdf_parsing_job", plan_idn=plan_idn, organization_id=str(organization_id))`
     - Update ParsingJob with the returned job_id
     - session.flush(), session.commit()
     - Return AIParsingSection(status="queued", job_id=job.job_id)

  **2. `get_primary_plan_idn(zoning_data: ZoningData | None) -> str | None`:**
  Extract the most relevant plan identifier from DSO zoning data (from Phase 3).
  - If zoning_data has plans, return the first plan's plan_id (already the most relevant per DSO API)
  - If no zoning_data or no plans, return None

  **3. `get_job_status(job_id, organization_id, session, arq_pool) -> AIParsingSection`:**
  Check job status for the polling endpoint. Steps:
  1. Query ParsingJob by job_id — verify organization_id matches (tenant isolation!)
  2. If no matching job found, return AIParsingSection(status="not_found")
  3. If job.status == "complete":
     - Fetch parsed data from CachedAPIResponse by plan_idn
     - Return AIParsingSection(status="complete", parsed_plan=data)
  4. If job.status == "failed":
     - Return AIParsingSection(status="failed", error_message=job.error_message)
  5. Otherwise: return AIParsingSection(status=job.status, job_id=job_id)

  Follow existing patterns:
  - Import from sqlalchemy: `select`
  - Import from app.models: ParsingJob
  - Import from app.models: CachedAPIResponse
  - Use `datetime.utcnow()` for naive datetimes
  - Direct db operations: `session.execute()`, `session.add()`, `session.flush()`, `session.commit()`
  - Use `logging.getLogger(__name__)` for logging
  </action>
