Note: The BAG WFS returns BUILDING footprints (panden). A parcel WITHOUT a pand in the result set means has_pand=False. The actual parcels come from the kadastral kaart WFS. For Phase 20 MVP, use the building footprints as the primary data source. Each pand from BAG WFS gets upserted into ParcelCache. The has_pand flag is set based on whether a building exists on the parcel.

Since we're fetching panden (buildings), not parcels, the approach for MVP is:
- Fetch all panden in the bbox from BAG WFS (these are buildings with geometries)
- For each pand, create a ParcelCache entry with has_pand=True
- The pand geometry represents the building footprint
- In future phases, a separate PDOK cadastral WFS query would get actual parcel boundaries

For this MVP, simplify: each BAG WFS feature becomes a ParcelCache entry representing a building. The `parcel_id` field uses the BAG identificatie. The `has_pand` is always True for these (they ARE panden). The scoring still works because vacant_land factor gives 0 points for has_pand=True.

Actually, to properly support the scoring (which rewards has_pand=False), we need actual parcel data too. But PDOK does not have a direct WFS for kadastrale percelen. The approach for MVP:
- Fetch panden from BAG WFS (we know where buildings are)
- Create ParcelCache entries for each pand with has_pand=True
- Mark parcels_total = number of panden found
- Score is based on available data (size, zoning, permits)

For a richer dataset in future: use PDOK kadastrale kaart WFS to get actual parcel boundaries, then cross-reference with BAG panden for has_pand detection.

**Phase 3: Process parcels and cross-reference (30-90% progress)**
- current_phase = "cross_referencing_bag"
- For each BAG WFS feature (pand):
  - Wrap in try/except to skip failures (user decision: skip and count)
  - Extract: identificatie, geometry, bouwjaar from feature properties
  - Compute area from geometry using Shapely
  - Upsert into ParcelCache:
    - Check if existing entry with (organization_id, parcel_id=identificatie)
    - If exists: update geometry, area_m2, has_pand=True
    - If not: create new ParcelCache entry
    - Set has_pand=True (these are building footprints, so buildings exist)
  - Query SRU for vergunningen near this location (if SRU client available):

    - Store in enrichment_data JSONB as `{"vergunningen": [...]}`
    - Note: SRU query is per-municipality, not per-parcel. Query once and cache for all parcels in same gemeente.
  - Compute score via `compute_opportunity_score(parcel_cache_entry)`
  - Create ScanResult linking scan to parcel with score and score_breakdown in flags
  - Every 10 parcels: update progress_pct (30 + idx/total * 60), parcels_processed, commit

- Optimization: Query SRU once per gemeente (not per parcel) and cache the result. The vergunningen enrichment should be a single bulk query at the start of Phase 3.
