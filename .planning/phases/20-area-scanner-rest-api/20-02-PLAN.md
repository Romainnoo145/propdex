<feature>
  <name>Parcel Opportunity Scoring</name>
  <files>backend/app/services/parcel_scoring.py, backend/tests/test_parcel_scoring.py</files>
  <behavior>
    Scoring function takes parcel data (not the ORM model directly -- use a protocol or dict-like interface for testability) and returns a ScoreBreakdown.

    **Scoring factors (fixed weights, documented for client conversations):**
    - **vacant_land (30 points max):** has_pand=False → 30, has_pand=True → 0
    - **size_optimal (25 points max):** 500-2000m² → 25, 300-500 or 2000-3000m² → 15, else → 5
    - **zoning_residential (25 points max):** bestemmingen contains type "Wonen" → 25, else → 0
    - **recent_permits (20 points max):** >=3 permits in last 3 years → 20, 1-2 permits → 10, 0 → 0

    **Category thresholds:** High >= 70, Medium >= 40, Low < 40

    **Test cases:**
    - Vacant + optimal size (1000m²) + Wonen + 3 permits → High (100)
    - Vacant + optimal size + Wonen + 0 permits → High (80)
    - Vacant + optimal size + no Wonen + 0 permits → Medium (55)
    - Has pand + small (200m²) + no Wonen + 0 permits → Low (5)
    - Vacant + large (5000m²) + Wonen + 1 permit → Medium (60)
    - None values for area_m2 → size_optimal defaults to 0
    - Empty bestemmingen list → zoning_residential = 0
    - None enrichment_data → recent_permits = 0
  </behavior>
  <implementation>
    Create a `@dataclass` called `ScoreBreakdown` with:
    - `total_score: float` (0-100)
    - `category: str` (High, Medium, Low)
    - `factors: dict[str, float]` (factor_name → contribution)

    Create `SCORING_WEIGHTS` dict for documentation transparency.

    Create `compute_opportunity_score(parcel_data)` function. The parcel_data parameter should accept any object with attributes: `has_pand`, `area_m2`, `bestemmingen`, `enrichment_data` (works with both ParcelCache ORM instances and test mocks).

    Internal helper `_score_recent_permits(enrichment_data: dict | None) -> float` extracts vergunningen and checks dates against 3-year window using `datetime.utcnow()`.

    Return ScoreBreakdown with factors dict containing all 4 factor keys (even when value is 0) so the API always returns a complete breakdown.
  </implementation>
</feature>
