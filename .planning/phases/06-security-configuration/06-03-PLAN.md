**1. Update get_db() in backend/app/core/database.py:**

Change the function signature to accept a `Request` parameter (FastAPI will inject it):

```python
from fastapi import Request

async def get_db(request: Request) -> AsyncGenerator[AsyncSession, None]:
    """
    FastAPI dependency that provides database session with RLS context.

    Extracts organization_id from request.state (set by TenantContextMiddleware)
    and sets PostgreSQL session variable for RLS policies.

    For authenticated requests: SET LOCAL app.current_tenant_id = org_id
    For unauthenticated requests: session variable is NOT set, RLS denies access (fail-closed)
    """
    async with async_session_factory() as session:
        # Get organization_id from middleware (if authenticated request)
        org_id = getattr(request.state, "organization_id", None)

        if org_id:
            # Set session variable for RLS policies (transaction-scoped via SET LOCAL)
            # SET LOCAL is safe with connection pooling — scoped to current transaction only
            await session.execute(
                text("SET LOCAL app.current_tenant_id = :org_id"),
                {"org_id": str(org_id)},
            )

        try:
            yield session
        finally:
            await session.close()
```

CRITICAL: Use `SET LOCAL` (not `SET`) — LOCAL scopes the variable to the current transaction, preventing context leakage across pooled connections.

**1. Rewrite backend/sql/rls_policies.sql with fail-closed policies for ALL tenant tables:**

The current file has:
- Only users and refresh_tokens (missing 5 tables)
- Fail-open policies (COALESCE fallback to organization_id = organization_id → always true)

Rewrite to cover ALL 7 tenant-scoped tables with fail-closed logic:

Tables needing RLS (all have organization_id via TenantMixin):
- users
- refresh_tokens
- cached_api_responses
- pdf_documents
- parsing_jobs
- saved_reports
- projects

Policy template for each table (fail-closed):
```sql
ALTER TABLE {table} ENABLE ROW LEVEL SECURITY;
-- Force RLS even for table owner (critical for non-superuser enforcement)
ALTER TABLE {table} FORCE ROW LEVEL SECURITY;

DROP POLICY IF EXISTS tenant_isolation_{table} ON {table};

CREATE POLICY tenant_isolation_{table} ON {table}
    FOR ALL
    USING (
        -- Fail-closed: if session variable is unset or empty, this evaluates to
        -- NULL::uuid which never equals organization_id, so access is denied.
        -- current_setting('app.current_tenant_id', TRUE) returns '' when unset (TRUE = missing_ok).
        -- NULLIF converts '' to NULL. ::uuid cast on NULL stays NULL.
        -- NULL = organization_id is always false in SQL → row denied.
        organization_id = NULLIF(current_setting('app.current_tenant_id', TRUE), '')::uuid
    )
    WITH CHECK (
        organization_id = NULLIF(current_setting('app.current_tenant_id', TRUE), '')::uuid
    );
```

IMPORTANT: Use `FORCE ROW LEVEL SECURITY` — this makes RLS apply to the table owner too. Without it, the table owner bypasses RLS. Only superusers and roles with BYPASSRLS attribute bypass RLS when FORCE is set.

NOTE: The organizations table does NOT get RLS — it's the root tenant entity.

Update the header comments to reflect the new status (production enforcement, not just defined).

Keep the verification SELECT query at the bottom but update to list all 7 tables.

-- Setup app_role for RLS-enforced application access
-- Run this as superuser (postgres) ONCE during initial deployment

-- Create app_role with LOGIN (required for direct connection)
-- NOT SUPERUSER ensures RLS policies are enforced
DO $$ BEGIN
    CREATE ROLE app_role WITH LOGIN PASSWORD 'CHANGE_ME_app_role_password';
    EXCEPTION WHEN duplicate_object THEN
        RAISE NOTICE 'Role app_role already exists, skipping creation';
END $$;

-- Grant connection and schema usage
GRANT CONNECT ON DATABASE crmplus TO app_role;
GRANT USAGE ON SCHEMA public TO app_role;

-- Grant DML on all current tables
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO app_role;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO app_role;

ALTER DEFAULT PRIVILEGES IN SCHEMA public
    GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_role;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
    GRANT USAGE, SELECT ON SEQUENCES TO app_role;

-- Verify role exists and permissions
SELECT rolname, rolsuper, rolcanlogin FROM pg_roles WHERE rolname = 'app_role';

def upgrade() -> None:

    ]
    for table in tables:
        op.execute(f'ALTER TABLE {table} ENABLE ROW LEVEL SECURITY')

        op.execute(f'DROP POLICY IF EXISTS tenant_isolation_{table} ON {table}')

            CREATE POLICY tenant_isolation_{table} ON {table}
                FOR ALL

                    organization_id = NULLIF(current_setting('app.current_tenant_id', TRUE), '')::uuid
                )
                WITH CHECK (
                    organization_id = NULLIF(current_setting('app.current_tenant_id', TRUE), '')::uuid
                )

def downgrade() -> None:
    tables = [
        'users', 'refresh_tokens', 'cached_api_responses',
