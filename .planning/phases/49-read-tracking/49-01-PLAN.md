Create `backend/app/models/change_read_state.py` with a new ChangeReadState model following the established pattern (Base, TenantMixin, no TimestampMixin since we only need read_at):

```python
class ChangeReadState(Base, TenantMixin):
    __tablename__ = "change_read_states"

    id: Mapped[uuid.UUID]  # PK, gen_random_uuid()
    user_id: Mapped[uuid.UUID]  # FK to users.id, ondelete=CASCADE
    change_id: Mapped[uuid.UUID]  # FK to change_records.id, ondelete=CASCADE
    read_at: Mapped[datetime]  # server_default CURRENT_TIMESTAMP

    __table_args__ = (
        UniqueConstraint("user_id", "change_id", name="uq_change_read_states_user_change"),
        Index("ix_change_read_states_user_change", "user_id", "change_id"),
    )
```

Key design decisions:
- ondelete=CASCADE on both FKs -- if user or change is deleted, read state is cleaned up
- UniqueConstraint ensures one read state per user per change (idempotent marks)
- No TimestampMixin (no updated_at needed -- read state is insert/delete only)
- TenantMixin for organization_id (multi-tenant isolation)

Add three new endpoints to `backend/app/monitoring/router.py`:

**1. POST /api/monitoring/changes/{change_id}/read** — Mark a single change as read
- Auth: get_current_active_user + get_current_organization_id
- Verify change belongs to organization (SELECT from change_records WHERE id=change_id AND organization_id=org_id)
- INSERT INTO change_read_states (organization_id, user_id, change_id) ON CONFLICT DO NOTHING (idempotent)
- Use `from sqlalchemy.dialects.postgresql import insert as pg_insert` for ON CONFLICT
- Return `{"status": "ok"}`

**2. DELETE /api/monitoring/changes/{change_id}/read** — Mark a single change as unread
- Auth: same as above
- DELETE FROM change_read_states WHERE user_id=current_user.id AND change_id=change_id
- Return `{"status": "ok"}`

**3. POST /api/monitoring/changes/read-all** — Mark all changes as read
- Accept optional query param `project_id: uuid.UUID | None = Query(None)`
- If project_id provided: mark all changes for that project as read
- If project_id omitted: mark all changes across the organization as read
- Implementation: SELECT all change_record IDs (filtered by project_id and organization_id), then bulk INSERT into change_read_states with ON CONFLICT DO NOTHING
- Return `{"status": "ok", "marked_count": N}`

IMPORTANT: The `read-all` endpoint path must be registered BEFORE the `{change_id}/read` path to avoid FastAPI treating "read-all" as a change_id parameter. Place the route definition for `/changes/read-all` above `/changes/{change_id}/read`.

**4. Update GET /api/monitoring/unread** to use per-change read state:
- Replace the current `last_viewed_at` comparison logic with a LEFT JOIN against change_read_states
- A change is "unread" if NO matching row exists in change_read_states for (user_id, change_id)
- Query pattern:
  ```sql
  SELECT project_id, COUNT(*) as unread_count
  FROM change_records cr
  LEFT JOIN change_read_states crs ON crs.change_id = cr.id AND crs.user_id = :user_id
  WHERE cr.organization_id = :org_id AND crs.id IS NULL
  GROUP BY cr.project_id
  ```
- Keep the existing response schema (UnreadDetailResponse with per_project breakdown)

**5. Update schemas/monitoring.py:**
- Add `MarkAllReadResponse` schema: `status: str`, `marked_count: int`
- Add `read_change_ids: list[str] | None = None` field to `ChangeRecordListResponse`

**6. Update GET /api/monitoring/changes to return read_change_ids:**
- After building the change_responses list, query ChangeReadState for the current user where change_id is IN the list of change IDs from the response
- Collect matching change_ids as strings
- Set `read_change_ids` on the ChangeRecordListResponse
- This allows the frontend to know which changes are already read without a separate API call

Keep all existing endpoints unchanged (backward compatible). The old `mark_viewed` and `last_viewed_at` logic can remain for now -- it will be deprecated in a future cleanup.

Rate limits: 60/minute for mark read/unread, 30/minute for mark-all-read.
