```python
from pydantic import BaseModel, field_validator

class ScoreWeightsConfig(BaseModel):
    preset: str = "standaard"
    potentie_risico_balance: float = 0.7  # 0.0 = full risico, 1.0 = full potentie
    potentie_weights: dict[str, int] = {}  # factor_name -> weight 1-10 (0 = disabled)
    risico_weights: dict[str, int] = {}

class SaveScoreWeightsRequest(BaseModel):
    preset: str
    potentie_risico_balance: float
    potentie_weights: dict[str, int]
    risico_weights: dict[str, int]

    @field_validator("potentie_risico_balance")
    @classmethod
    def validate_balance(cls, v: float) -> float:
        if not 0.0 <= v <= 1.0:
            raise ValueError("Balance must be between 0.0 and 1.0")
        return round(v, 2)

    @field_validator("potentie_weights", "risico_weights")
    @classmethod
    def validate_weights(cls, v: dict[str, int]) -> dict[str, int]:
        for name, w in v.items():
            if not 0 <= w <= 10:
                raise ValueError(f"Weight for {name} must be 0-10")
        # At least 3 active (non-zero) — validated at endpoint level for cross-field check
        return v

class ScoreWeightsResponse(BaseModel):
    weights: ScoreWeightsConfig
    is_custom: bool  # True if org has non-default weights
    job_id: str | None = None  # Set after save triggers re-score

class RescoreJobStatus(BaseModel):
    status: str  # queued, in_progress, complete, failed
    processed: int = 0
    up_count: int = 0
    down_count: int = 0
    unchanged_count: int = 0
    avg_delta: float = 0.0
```

**1. Create `backend/app/jobs/rescore_weights.py`:**

```python
async def rescore_weights_job(ctx: dict, *, organization_id: str) -> dict:
```

Implementation:
- Create async DB session (same pattern as `area_scan_job`)
- Load org from organizations table by ID, get `org.score_weights`
- If no custom weights, return early with `{processed: 0}` (nothing to do)
- Extract `potentie_weights`, `risico_weights`, `potentie_risico_balance` from config
- Query all `scan_results` where:
  - `scan_results.scan_id` in (SELECT id FROM area_scans WHERE organization_id = :org_id)
  - `scan_results.flags` IS NOT NULL
- Process in batches of 500 rows (to avoid loading 137k rows at once):
  - For each row, call `_rescore_from_breakdown(sr.flags, custom_weights, balance)` helper
  - The helper (from 108-RESEARCH.md Pattern 3):
    - Reads `flags["score_breakdown"]` — each factor has `genormaliseerde_score` and `categorie`
    - Checks `score_model_version == "score-v3.0"` — skip non-v3.0 rows
    - For each factor: `bijdrage = genormaliseerde_score × custom_weight` (or default if not specified)
    - Sum potentie/risico raw scores, divide by dynamic max (sum of active weights per category)
    - Apply new formula: `overall = potentie_score × (1 - min(0.5, risico_score/100 × (1-balance)))`
  - Track deltas: old_score vs new_overall
  - Update `sr.score = new_overall`
  - Update `sr.flags["scores"] = {"potentie_score": ..., "risico_score": ..., "overall": ...}`
  - Update each factor's `bijdrage` and `gewicht` in `flags["score_breakdown"]`
  - `db.flush()` every 500 rows

- After all batches: `db.commit()`
- Return summary dict: `{processed, up_count, down_count, unchanged_count, avg_delta}`

**CRITICAL:** Do NOT call `compute_score_v3()`. Only read `genormaliseerde_score` from stored `score_breakdown` and re-multiply by new weights. This is a weights-only re-application.

**CRITICAL:** Skip rows where `flags.get("score_model_version") != "score-v3.0"` — old v2.1 rows don't have `genormaliseerde_score` or `categorie`.
