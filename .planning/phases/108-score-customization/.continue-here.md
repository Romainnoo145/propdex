<context>
The backfill tool in `backend/app/tools/backfill_enrichment.py` iterates per-wijk scan. After coordinate enrichment (bodem + 4 environmental), it reloads parcels and runs address enrichment. The address pipeline has 3 steps:

1. `_resolve_addresses_batch()` — calls `reverse_geocode_rd_point_full(centroid)` per parcel via PDOK Locatieserver → returns postcode, VBO ID, nummeraanduiding ID
2. `batch_fetch_postcode_enrichment()` — uses postcodes for SRU vergunningen + funderingsrisico
3. `batch_fetch_address_enrichment()` — uses VBO IDs for energielabel + nummeraanduiding IDs for WOZ

Step 1 returns 0 results for ALL parcels across ALL 21 wijken. No warnings logged. The function is in `backend/app/services/parcel_addressing.py` and uses `find_bag_building_lookup_point()` which checks for BAG building overlap before reverse geocoding — this might be filtering out parcels that don't have buildings overlapping them (empty parcels, parcels where BAG WFS returns nothing).

Key files to investigate:
- `backend/app/services/parcel_addressing.py` — reverse_geocode_rd_point_full + find_bag_building_lookup_point
- `backend/app/tools/backfill_enrichment.py` lines 332-375 — _resolve_addresses_batch
- `backend/app/government_apis/pdok_locatieserver.py` — PDOK API client
- `backend/app/government_apis/bag_wfs.py` — BAG building WFS client

DB check confirmed: 0/63,817 parcels have energielabel, woz, vergunningen, or funderingsrisico keys in flags JSONB.
