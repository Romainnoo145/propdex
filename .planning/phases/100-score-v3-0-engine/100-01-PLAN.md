**Data model:**
- `FactorResult` dataclass: `waarde: Any`, `genormaliseerde_score: float` (0-1), `gewicht: float`, `bijdrage: float` (score * gewicht), `categorie: Literal["potentie", "risico"]`, `toelichting_kort: str`, `toelichting_lang: str`, `data_bronnen: list[str]`, `missing: bool` (True if data was unavailable)
- `ScoreV3Result` dataclass: `potentie_score: float` (0-100), `risico_score: float` (0-100), `overall: float` (potentie - risico, can be negative), `category: str` (Hoog/Gemiddeld/Laag based on overall), `score_breakdown: dict[str, FactorResult]`, `model_version: str = "score-v3.0"`, `missing_factor_count: int`

**Main function signature:**
```python
def compute_score_v3(
    parcel_data: dict[str, Any],       # flags_dict-style data from scan_results
    neighborhood_metrics: dict[str, Any] | None = None,  # CBS wijk data from area_scans
) -> ScoreV3Result:
```
`parcel_data` contains: `area_m2`, `has_pand`, `pand_status`, `bouwjaar`, `bestemmingen` (list of dicts), `building_metrics` (dict), `vacancy_signal`, `vacancy_confidence`, `market_signals` (dict or None), `bodem` (dict), `bodemtype` (dict), `funderingsrisico` (dict), `energielabel` (dict), `vergunningen` (dict).

**8 Potentie factor functions** (each returns FactorResult):
1. `_score_vrije_grond(parcel_data)` — gewicht=12. Uses `area_m2` vs `building_metrics.pand_oppervlakte_m2`. Score = ratio of unbuilt area. Log-scale normalization for large parcels.
2. `_score_optoppotentie(parcel_data)` — gewicht=10. Uses `building_metrics.{max,actual}_{bouwhoogte,bouwlagen}`. Score based on headroom ratio. Missing max_bouwlagen (0% dekking) → mark as missing.
3. `_score_bestemming(parcel_data)` — gewicht=12. Uses `bestemmingen[].type`. "Wonen" = 1.0, "Gemengd"/"Centrum" = 0.7, "Maatschappelijk" = 0.4, other = 0.2. Binary-like scale.
4. `_score_leegstand(parcel_data)` — gewicht=8. Uses `vacancy_signal`. "leeg_perceel" = 1.0, "leegstaand_pand" = 0.8, "onbekend" = 0.3, "in_gebruik" = 0.0.
5. `_score_funda_frictie(parcel_data)` — gewicht=5. Uses `market_signals.listing_duration_days` + `price_change_count`. Long duration + price drops = higher score (motivated seller). No market_signals → missing.
6. `_score_perceelgrootte(parcel_data)` — gewicht=12. Uses `area_m2`. Log-scale normalization: log(area)/log(10000). Clamp 0-1.
7. `_score_demografie(neighborhood_metrics)` — gewicht=8. Uses CBS `demografie.aantal_inwoners`, `inkomen.gem_gestandaardiseerd`, `huishoudens.totaal`. Growing/affluent areas score higher. No neighborhood_metrics → missing.
8. `_score_vergunning_succeskans(neighborhood_metrics)` — gewicht=13. Uses pre-computed juridisch klimaat from neighborhood_metrics if available. No data → missing (score neutral per missing data strategy).

**9 Risico factor functions:**
1. `_score_funderingsrisico(parcel_data)` — gewicht=15. Uses `funderingsrisico.fgr` + `bodemtype.dominant_type` + `bouwjaar`. "hoog" + klei/veen + pre-1970 = 1.0. No data → missing with -10% penalty (critical).
2. `_score_asbest(parcel_data)` — gewicht=6. Uses `bouwjaar` (< 1994 = risk). Score increases for industrial function in bestemmingen.
3. `_score_bodemverontreiniging(parcel_data)` — gewicht=7. Uses `bodem.has_known_contamination` + `dossiers_count`. Binary + severity. No data → missing with -10% penalty (critical).
4. `_score_monument(parcel_data)` — gewicht=5. Check bestemmingen for "Waarde" types (proxy for monument/erfgoed). Binary.
5. `_score_bestemmingswijziging(parcel_data)` — gewicht=8. Inverse of bestemming compatibiliteit. Non-wonen bestemming = higher risk.
6. `_score_constructieve_staat(parcel_data)` — gewicht=7. Uses `bouwjaar` + `energielabel.energieklasse`. Old building + poor energy label = higher risk.
7. `_score_juridisch_klimaat(neighborhood_metrics)` — gewicht=8. Same data as vergunning_succeskans, inverted. No data → missing.
8. `_score_criminaliteit(neighborhood_metrics)` — gewicht=6. Uses `criminaliteit.per_1000_inwoners`. Linear normalization: higher crime = higher risk. No data → missing.
9. `_score_max_hoogte_bereikt(parcel_data)` — gewicht=5. Uses building_metrics headroom. If actual >= max → 1.0 (no room). Missing data → missing.

**Normalization framework:**
- `_normalize_log(value, max_value)` — for continuous variables (perceelgrootte, area)
- `_normalize_linear(value, min_val, max_val)` — for ranges (criminaliteit)
- `_normalize_binary(condition)` — for yes/no (monument, asbest)
- All return 0-1 float

**Missing data strategy** (implement in `compute_score_v3`):
1. Default: missing factor gets neutral score = 0.5 (midpoint)
2. Critical risk factors (funderingsrisico, bodemverontreiniging, asbest): neutral + 10% penalty = 0.5 + 0.1*max_score of factor
3. If >20% factors in a category missing: redistribute weights proportionally over present factors

**Overall calculation:**
- Raw potentie = sum of potentie bijdragen (max 80)
- Raw risico = sum of risico bijdragen (max 67)
- `potentie_score` = (raw_potentie / 80) * 100
- `risico_score` = (raw_risico / 67) * 100
- `overall` = potentie_score - risico_score (can be negative; range roughly -100 to +100)
- `category` = "Hoog" if overall > 40, "Gemiddeld" if > 10, "Laag" otherwise

**Narrative templates per factor** — each factor function must also generate:
- `toelichting_kort`: 1-sentence Dutch summary using f-string with actual values (e.g., "42% vrije grond — geschikt voor zelfstandige nieuwbouw")
- `toelichting_lang`: Full paragraph Dutch for rapport (context + onderbouwing + aanbeveling)
- `data_bronnen`: list of source strings (e.g., ["BAG", "Kadaster"])

These are deterministic template-based strings (NO AI calls). Patterns: look at frontend `PotentieLayer.tsx` narrative functions for style reference but write in backend Python.
