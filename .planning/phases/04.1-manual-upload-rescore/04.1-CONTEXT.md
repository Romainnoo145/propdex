<domain>
## Phase Boundary

**Goal:** Wire `rescore_parcels_for_document` ARQ enqueue into the manual PolicyDocument upload path so admin uploads via the M049/S04 data-bronnen hub trigger cascade re-scoring (parity with the weekly auto-ingest cron). Closes the INT-04 gap where uploaded docs flip `status='live'` on the admin dashboard but do NOT propagate to `scan_results` until the weekly cron runs.

**Two wire-points:**
1. **Upload route** (`backend/app/policy_documents/router.py` upload handler) — fires on every admin upload of a gated source_key.
2. **Probe orchestrator** (`backend/app/admin/data_source_probe_orchestrator.py`) — fires once per pre-existing M045/S05-era document the first time the data-bronnen hub renders that gemeente (`missing → live` transition only).

**Out of scope for this phase:**
- Generalised factor registry / dynamic extractor lookup (premature for 1 extractor — deferred until M050+ adds ≥3 keys)
- Per-source_key extractor implementations (planned in M050/M051/M054/M055/M056/M057)
- PUT/DELETE/version-rollback wire-up (capture as follow-up if needed)
- One-shot backfill script for orgs that never view the data-bronnen hub

</domain>

<decisions>
## Implementation Decisions (LOCKED via /plan-eng-review 2026-05-16)

### Source_key gate strategy [Decision 1 — chose 1B]
- A shared module-level constant `CASCADE_RESCORE_SOURCE_KEYS: frozenset[str] = frozenset({"woonvisie"})` lives in `backend/app/jobs/rescore_cascade_job.py` (near top, after imports).
- Both wire sites import this constant and gate enqueue on `if source_key in CASCADE_RESCORE_SOURCE_KEYS`.
- M050+ extractors land by adding their source_key string to this frozenset — no other wire-site changes.
- Rationale: explicit > clever. No magic registry. Auditable at one location.

### Probe orchestrator wire [Decision 2 — chose 2B]
- `data_source_probe_orchestrator.run_opportunistic_probes` enqueues rescore ONLY on `missing → live` transitions.
- Implementation: capture `previous_status` for each row BEFORE the commit. After commit, iterate rows where `previous_status != 'live' AND new_status == 'live' AND source_key in CASCADE_RESCORE_SOURCE_KEYS`; enqueue rescore for the associated `policy_document_id`.
- Dedup per `document_id` within a single call (defensive — same gemeente shouldn't have two missing→live transitions for the same doc in one probe run).
- Subsequent GETs that find the row already `live` do NOT re-enqueue.

### DRY [Decision 3 — chose 3B]
- The single `CASCADE_RESCORE_SOURCE_KEYS` frozenset covers both wire sites. No further helper / abstraction.

### Error handling pattern (mirror existing reference)
- Both wire sites use try/except around `arq_pool.enqueue_job(...)` and call `logger.warning(...)` on failure.
- Reference: `backend/app/jobs/auto_ingest_job.py:64-80` (M047/S05 path).
- Mirror: `backend/app/policy_documents/router.py:121-130` (existing `document_summary_job` enqueue — same try/except shape).
- Upload route MUST still return 201 even if rescore enqueue fails. Worst case: weekly cron picks it up.

### Idempotency
- `rescore_parcels_for_document(ctx, *, document_id)` is already cache-keyed on `(parcel_id, policy_document_id, factor_id, SCHEMA_VERSION)` via `extract_factor(... force_refresh=False)`. Duplicate enqueues = cache hits, no Claude calls.
- No additional dedup needed at the ARQ level.

### Claude's Discretion (implementation details — not locked, planner decides)
- Exact code location/ordering of the constant declaration (top vs. before function).
- Test file location (extend existing test file vs. new file) — prefer extending existing.
- Mock pattern for `arq_pool` in tests — use whatever pattern existing tests use.
- Whether to log on the no-op case (non-woonvisie source_key) — likely skip log to avoid spam.

</decisions>
