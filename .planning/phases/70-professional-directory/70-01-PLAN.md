5. Generate Alembic migration:
   ```bash
   cd backend && alembic revision --autogenerate -m "add professionals table"
   ```
   Then MANUALLY clean the generated migration:
   - Remove all PostGIS/tiger/topology noise (known pattern — see STATE.md)
   - Keep only `create_table('professionals', ...)` and indexes
   - After `create_table`, add RLS setup:
     ```python
     op.execute("ALTER TABLE professionals ENABLE ROW LEVEL SECURITY")
     op.execute("ALTER TABLE professionals FORCE ROW LEVEL SECURITY")
     op.execute("""
         CREATE POLICY professionals_select ON professionals
             FOR SELECT
             USING (TRUE)
     """)
     ```
   - No INSERT/UPDATE/DELETE policy needed — app_role has table-level GRANT, and RLS only restricts commands that have matching policies
   - downgrade: `op.execute("DROP POLICY IF EXISTS professionals_select ON professionals")` then `op.drop_table('professionals')`

6. Apply migration: `cd backend && alembic upgrade head`

IMPORTANT: Do NOT use TenantMixin. The Professional model has NO organization_id — it is a platform-wide resource visible to all tenants. This is the critical architectural pattern for DIR-03.
