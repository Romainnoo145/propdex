  <action>
    **Step 1: Run address backfill for Venlo stragglers.**
    After all scans complete, run the backfill tool to resolve addresses for any parcels that missed PDOK reverse geocoding during the scan:
    ```bash

        --gemeente-code GM0983 \
        --only-scanned-parcels \
        --scan-status completed
    ```
    This resolves addresses for parcels where has_pand=True but address is NULL, using BAG building overlap point for reverse geocoding.

    **Step 2: Run the validation tool.**
    ```bash
    cd backend && python -m app.tools.validate_scan_data --gemeente-code GM0983
    ```
    This prints:
    - Per-wijk validation table with bouwjaar, address, and pand_status rates
    - Score-vs-pand_status consistency check
    - Overall pass/fail verdict

    **Step 3: Evaluate results.**
    - Bouwjaar rate >= 80% for all wijken -> PASS
    - Address rate >= 50% for all wijken -> PASS (PDOK rate limits may cause some misses)
    - Pand status rate >= 80% -> PASS
    - Score consistency: in_gebruik avg < buiten_gebruik avg -> PASS

    **If any wijk fails validation:** Investigate specific parcels. Common causes:
    - Low address rate: PDOK rate limiting hit during scan. Re-run backfill for specific scan.

    - Score inconsistency: Scoring formula bug. Check parcel_scoring.py pand_status_signal values.
