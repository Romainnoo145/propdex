  <name>Task 1: Build coordinate-based enrichment backfill with wijk-batch processing</name>
  <files>backend/app/tools/backfill_enrichment.py</files>
  <action>
Create `backfill_enrichment.py` following the `backfill_scan_scores_v3.py` pattern exactly (argparse CLI, async _run, org iteration, batch pagination, SET app.current_tenant_id).

**CLI arguments:**
- `--gemeente` (optional, string) — filter scans by gemeente name (default: all)
- `--scan-id` (optional, UUID) — process single scan
- `--batch-size` (int, default 500) — pagination batch size
- `--dry-run` (flag) — log what would change without writing
- `--skip-coordinate` (flag) — skip coordinate-based enrichment (for resume after partial run)
- `--skip-address` (flag) — skip address-based enrichment
- `--skip-rescore` (flag) — skip v3.0 re-scoring pass
- `--inter-wijk-delay` (float, default 5.0) — seconds to pause between wijk batches

**Processing flow per wijk scan:**

1. **Load data:** Query ScanResult + ParcelCache joined rows (same JOIN pattern as backfill_scan_scores_v3.py). Filter to completed scans only (AreaScan.status == 'completed').

2. **Skip-already-enriched check:** For each scan_result, check if all 10 enrichment keys exist in flags. Count and skip fully-enriched parcels. Log skip count per wijk.

3. **Coordinate-based enrichment (6 sources):**
   - Extract centroids from ParcelCache.geometry using `geoalchemy2.shape.to_shape(geom).centroid` — produces (parcel_id, rd_x, rd_y) tuples.
   - Call `batch_fetch_bodem_data(centroids, client)` — returns {parcel_id: {bodem, bodemtype}}.
   - Call `batch_fetch_environmental_data(centroids, client)` — returns {parcel_id: {natura2000, overstromingsrisico, geluid, luchtkwaliteit}}.
   - Both functions already handle deduplication (1m for bodem, 50m for env) and concurrency (Semaphore-based).

4. **Merge coordinate enrichment into flags:** For each scan_result, read existing flags dict, merge new keys using the "skip existing" pattern: `if key not in existing_flags and data.get(key): existing_flags[key] = data[key]`. This preserves bodem/bodemtype if already present from original Phase 3b.

5. **Flush + commit per wijk batch.** Log progress: wijk N/21, parcels enriched, parcels skipped.

6. **Inter-wijk delay:** `await asyncio.sleep(inter_wijk_delay)` between wijk batches to avoid rate limit exhaustion.

**Important details:**
- Use `async_session_factory()` for DB sessions (same as backfill_scan_scores_v3.py).
- Use `httpx.AsyncClient(timeout=30.0)` for external API calls (shared across all batch_fetch calls within a wijk).
- Filter scans by gemeente: JOIN AreaScan on ScanResult.scan_id, filter by `AreaScan.gemeente_naam == gemeente` (case-insensitive ILIKE).
- Wrap each wijk's coordinate enrichment in try/except — non-fatal, log error and continue to next wijk.
- Log totals at end: total parcels processed, enriched, skipped, errors.

Do NOT implement address-based enrichment in this task — that comes in Task 2.

<task type="auto">
  <name>Task 2: Add address-based enrichment pass and v3.0 re-scoring</name>
  <files>backend/app/tools/backfill_enrichment.py</files>
  <action>
Extend the backfill tool with address-based enrichment (Phase 5b equivalent) and v3.0 re-scoring.

**Address re-resolution (needed for VBO/nummeraanduiding IDs):**
- VBO IDs and nummeraanduiding IDs are NOT stored in parcel_cache — they were discarded after the original scan.
- For each parcel with a centroid, call `reverse_geocode_rd_point_full(rd_x, rd_y, client)` from `parcel_addressing.py`. This returns `AddressResolution(address, postcode, nummeraanduiding_id, vbo_id)`.
- Batch address resolution with concurrency Semaphore(10) to respect PDOK Locatieserver rate limits (~50k/hr).
- Build three dicts from resolved addresses: `postcodes_by_parcel`, `vbo_ids_by_parcel`, `nummeraanduiding_ids_by_parcel`.
- Skip parcels where address is None / geometry is None.

**Address-based enrichment (4 sources):**
- Call `batch_fetch_postcode_enrichment(postcodes_by_parcel, client)` — returns {parcel_id: {vergunningen, funderingsrisico}}.
- Call `batch_fetch_address_enrichment(vbo_ids_by_parcel, nummeraanduiding_ids_by_parcel, client)` — returns {parcel_id: {energielabel, woz}}.
- Both functions handle deduplication internally (postcode dedup for SRU/funderingsrisico, VBO/nummeraanduiding dedup for EP-Online/WOZ).

**Merge address enrichment into flags:** Same "skip existing" pattern as coordinate enrichment. Merge vergunningen, funderingsrisico, energielabel, woz keys.

**V3.0 Re-scoring pass (after all enrichment):**
- After both coordinate and address enrichment are merged, iterate over all scan_results again.
- Load neighborhood_metrics from AreaScan (same `_load_neighborhood_metrics` pattern as backfill_scan_scores_v3.py).
- Build parcel_data using `_build_parcel_data(pc, flags)` (copy helper from backfill_scan_scores_v3.py).
- Call `compute_score_v3(parcel_data, nbhd)`.
- Update sr.score, sr.flags with new score keys (scores, score_breakdown, score_model_version, category). Remove old v2.1 keys (factors, subscores).
- Flush + commit per batch.

**EP-Online API key check:** At startup, check `from app.core.config import settings` → `settings.EP_ONLINE_API_KEY`. If empty/None, log warning "EP_ONLINE_API_KEY not configured — energielabel enrichment will be skipped" and proceed.

**Resume support:** The `--skip-coordinate` and `--skip-address` flags allow resuming after partial completion. The `--skip-rescore` flag allows running enrichment without re-scoring (useful for debugging).

**Entry point:** `if __name__ == "__main__": main()` — invokable as `python -m app.tools.backfill_enrichment --gemeente Venlo`.

**Logging:** Use standard logging with format matching existing tools. Log per-wijk: address resolution count, postcode enrichment count, address enrichment count, re-scored count.
