<task type="auto">
  <name>Task 3: Create cn() utility and add ESLint tailwind enforcement</name>
  <files>
    frontend/src/lib/utils.ts
    frontend/eslint.config.js
  </files>
  <action>
    1. Create `frontend/src/lib/utils.ts` with the cn() utility:
       ```typescript
       import { type ClassValue, clsx } from 'clsx';
       import { twMerge } from 'tailwind-merge';

       /**
        * Merge Tailwind CSS classes without conflicts.
        * Combines clsx (conditional classes) with tailwind-merge (deduplication).
        * Use this in ALL component className props.
        */
       export function cn(...inputs: ClassValue[]): string {
         return twMerge(clsx(inputs));
       }
       ```

    2. Update `frontend/eslint.config.js` to add eslint-plugin-tailwindcss:
       - First, install the dev dependency: `cd frontend && pnpm add -D eslint-plugin-tailwindcss`
       - Add a new config block for tailwindcss rules:
         ```javascript
         import tailwind from 'eslint-plugin-tailwindcss';
         ```
       - Add rules block (as a separate config object, AFTER the existing TypeScript config):
         ```javascript
         {
           plugins: { tailwindcss: tailwind },
           files: ['**/*.{ts,tsx}'],
           rules: {
             'tailwindcss/no-arbitrary-value': 'warn',
           },
         }
         ```
       - Use 'warn' (not 'error') initially — there may be existing arbitrary values in the codebase that need gradual migration.
       - Do NOT add 'tailwindcss/no-custom-classname' yet — it requires careful whitelist configuration.

    3. Verify the cn() utility compiles by running TypeScript check.
  </action>
