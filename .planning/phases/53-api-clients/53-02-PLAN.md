**Class: `RCELinkedDataClient`**

The existing `rce_monuments.py` handles PDOK/Solr-based spatial search. This new file handles RCE Linked Data for monument detail enrichment by rijksmonumentnummer.

**Strategy for detail fields (CRITICAL — research found the REST API lacks detail fields):**

The `rest-api-rijksmonumenten` endpoint only returns basic fields (rijksmonumentnummer, cultuurhistorischObjectnummer, datum). The rich detail fields (redengevende omschrijving, oorspronkelijkeFunctie, bouwperiode) require a different approach.

Implement a **two-step fetch strategy:**

1. **Step 1: REST API query** — `GET https://api.linkeddata.cultureelerfgoed.nl/queries/rce/rest-api-rijksmonumenten/run?rijksmonumentnummer={nr}` with `Accept: application/ld+json`. Extract the `@id` of the Rijksmonument node (the `cultuurhistorischObjectnummer`) and `datumInschrijvingInMonumentenregister`.

2. **Step 2: Dereference the monument resource** — Fetch `https://linkeddata.cultureelerfgoed.nl/cho-kennis/id/rijksmonument/{cultuurhistorischObjectnummer}` with `Accept: application/ld+json`. This should return the full CEO ontology representation with all detail fields including `heeftOorspronkelijkeFunctie`, `heeftBouwstijl`, `heeftBouwperiode`, and `kennisregistratie` (which contains `redengevendeOmschrijving`).

If Step 2 fails or returns no additional fields, gracefully degrade: return RCEMonumentDetail with only the basic fields from Step 1 (rijksmonumentnummer + datum). Log a WARNING for investigation but do NOT fail the request — the existing PDOK spatial match already confirms monument status.

**JSON-LD Parsing Helpers:**

```python
CEO_NS = "https://linkeddata.cultureelerfgoed.nl/def/ceo#"

def _find_node_by_type(nodes: list[dict], type_suffix: str) -> dict | None:
    """Find a node in JSON-LD graph by type URI suffix."""

def _get_literal(node: dict, predicate: str) -> str | None:
    """Extract @value from a JSON-LD predicate. Uses CEO_NS prefix."""

def _get_uri_label(node: dict, predicate: str) -> str | None:
    """Extract last path segment from a URI value and convert to human-readable Dutch label."""

def _resolve_uri_to_label(uri: str) -> str:
    """Convert RCE URI like '/id/functie/woonhuis' to 'Woonhuis' (capitalize, strip path)."""

def _get_all_literals(node: dict, predicate: str) -> list[str]:
    """Extract all @value entries for a multi-valued predicate."""
```

**URI-to-label resolution (user decision: resolve at fetch time, not display time):**
- For function URIs: extract last path segment, capitalize (e.g., `https://.../functie/woonhuis` -> `"Woonhuis"`)
- For style URIs: same pattern (e.g., `https://.../bouwstijl/neoclassicisme` -> `"Neoclassicisme"`)
- Multi-valued fields (functions, complexes) stored as List[str] per user decision

**Method: `async def get_detail_by_monument_number(self, rijksmonumentnummer: str, client: httpx.AsyncClient) -> RCEMonumentDetail | None`**
- Use `async with rce_detail_limiter:` for rate limiting (import from rate_limiter.py, already exists)
- Step 1: REST API query to get cultuurhistorischObjectnummer
- Step 2: Dereference to get full detail
- Parse JSON-LD, extract all available fields into RCEMonumentDetail
- Map to RCEMonumentDetail with these field mappings:
  - `rijksmonumentnummer` -> from Step 1
  - `redengevende_omschrijving` -> from Step 2 kennisregistratie/redengevendeOmschrijving
  - `oorspronkelijke_functie` -> from Step 2 heeftOorspronkelijkeFunctie (resolve URI to Dutch label)
  - `bouwjaar_van` / `bouwjaar_tot` -> from Step 2 heeftBouwperiode
  - `architect` -> from Step 2 heeftOntwerper (if available)
  - `bouwstijl` -> from Step 2 heeftBouwstijl (resolve URI to Dutch label)
  - `monument_register_url` -> `f"https://monumentenregister.cultureelerfgoed.nl/monumenten/{rijksmonumentnummer}"`
- Catch `APINotFoundError`: return None (rare — monument exists in PDOK but not in Linked Data)
- Catch `httpx.TimeoutException`: raise `GovernmentAPIError("rce-linked-data", "Request timed out")`
- Log at INFO level: request rijksmonumentnummer, fields found/missing

**Three-state contract:**
- Data found -> return RCEMonumentDetail (with as many fields as available)
- No data in API (404/empty) -> return None
- API error/timeout -> raise GovernmentAPIError

**Module-level singleton:** `rce_linked_data_client = RCELinkedDataClient()`

**Labeling (RCE-04):** The returned `RCEMonumentDetail` model implicitly satisfies RCE-04 — the presence of `rijksmonumentnummer` and the model name `RCEMonumentDetail` confirm source is RCE. The frontend (Phase 56) uses this to display "Rijksmonument (RCE)" labels. No "monument_type" string needed at client level.
