```python
async def search_by_court(
    self,
    court_codes: list[str],
    client: httpx.AsyncClient,
    max_results: int = 100,
    date_from: str | None = None,
    date_to: str | None = None,
) -> list[dict]:
```

Implementation details:

1. **Search broadly, filter client-side:** Call the Rechtspraak API with `subject=omgevingsrecht`, `max=max_results`, `sort=DESC`, `return=DOC`. Do NOT use the `creator` parameter (returns 0 results when combined with `subject` -- confirmed in research).

2. **Date range filtering:** The official API uses a `date` parameter (NOT `sd`/`ed`). For a range, pass two `date` values. Use httpx list-of-tuples for params to support duplicate keys:
   ```python
   params: list[tuple[str, str]] = [
       ("subject", OMGEVINGSRECHT_URI),
       ("max", str(max_results)),
       ("sort", "DESC"),
       ("return", "DOC"),
   ]
   if date_from:
       params.append(("date", date_from))
   if date_to:
       params.append(("date", date_to))
   ```

3. **Client-side ECLI prefix filtering:** After fetching results, filter by court code using `extract_court_code()` from `ecli_registry.py`:
   ```python
   from app.government_apis.ecli_registry import extract_court_code

   court_code_set = set(court_codes)
   filtered = [
       r for r in results
       if extract_court_code(r["ecli"]) in court_code_set
   ]
   ```

4. **Logging:** Log the search parameters, total results before filtering, and filtered count. This is critical for debugging filter effectiveness.

5. **Error handling:** Use the same `rechtspraak_limiter` + `retry_with_backoff` pattern as `search_jurisprudence`. Raise `APITimeoutError` on timeout, `GovernmentAPIError` on parse failure.

6. **Reuse XML parsing:** Extract the XML parsing logic from `search_jurisprudence` into a private `_parse_search_results(response_content: bytes) -> list[dict]` method to avoid code duplication. Both `search_jurisprudence` and `search_by_court` should use this shared method.

Do NOT modify the existing `search_jurisprudence()` signature or behavior -- it is still used by the `/search` endpoint.

**1. Create `backend/app/jobs/ruling_ingestion.py`:**

Follow the exact same pattern as `jurisprudence_analysis.py` (engine-per-invocation, session_factory, try/finally with engine.dispose()):

```python
async def ruling_ingestion_job(
    ctx: dict,
    gemeente_naam: str,
) -> dict:
```

Job logic:
1. Create engine + session_factory (same pattern as `jurisprudence_analysis_job`)
2. Look up court codes via `get_court_codes_for_gemeente(gemeente_naam)` from ecli_registry
3. If no court codes found, return `{"status": "error", "error": "Unknown gemeente"}`
4. Search via `rechtspraak_client.search_by_court(court_codes=court_codes, max_results=100)`
5. Batch fetch full documents using `asyncio.Semaphore(5)` for concurrency control:
   ```python
   sem = asyncio.Semaphore(5)
   async def fetch_one(ecli: str) -> dict | None:
       async with sem:
           try:
               return await rechtspraak_client.get_jurisprudence_document(ecli=ecli, client=http_client)
           except Exception as e:
               logger.warning("Failed to fetch %s: %s", ecli, e)
               return None

   tasks = [fetch_one(r["ecli"]) for r in search_results]
   docs = await asyncio.gather(*tasks)
   ```
6. For each fetched document, upsert into `RulingCache`:
   - Use `select().where(RulingCache.ecli == doc["ecli"])` to check existence
   - If exists: update `full_text`, `fetched_at`, `updated_at`
   - If new: create RulingCache with `ecli`, `court_code` (extracted via `extract_court_code`), `instantie`, `datum_uitspraak`, `title` (from search result), `summary` (from search result), `full_text` (from document fetch), `gemeente_query=gemeente_naam`, `fetched_at=datetime.utcnow()`
   - Use `db.add() / db.flush()` pattern, commit once at the end
7. Return `{"status": "completed", "gemeente": gemeente_naam, "cached": N, "fetched": M}`
8. In `finally` block: `await engine.dispose()`

Use `datetime.utcnow()` (NOT `datetime.now(timezone.utc)`) per project convention.

**3. Update `backend/app/api/endpoints/jurisprudence.py`:**

Add a new endpoint `GET /rulings/{gemeente_naam}` that:
1. Checks ruling_cache for existing rulings where `gemeente_query = gemeente_naam`
2. Checks TTL: if most recent `fetched_at` is older than 7 days (or no rows exist), enqueue `ruling_ingestion_job` via `request.app.state.arq_pool.enqueue_job("ruling_ingestion_job", gemeente_naam)`. Use a job dedup key like `f"ruling_ingest:{gemeente_naam}"` to prevent duplicate jobs.
3. Returns cached rulings immediately (even if stale -- the background job will refresh):
   ```python
   @router.get("/rulings/{gemeente_naam}")
   async def get_gemeente_rulings(
       gemeente_naam: str,
       request: Request,
       db: AsyncSession = Depends(get_db),
       current_user=Depends(get_current_active_user),
       date_from: str | None = Query(None, description="Filter from date YYYY-MM-DD"),
       date_to: str | None = Query(None, description="Filter to date YYYY-MM-DD"),
   ):
   ```
4. Query `ruling_cache` filtered by `gemeente_query = gemeente_naam`, optionally filtered by `datum_uitspraak` range if date_from/date_to provided
5. Order by `datum_uitspraak DESC`
6. Return `{"status": "success", "rulings": [...], "ingestion_status": "fresh|refreshing|pending", "count": N}`
   - `fresh`: cache hit within 7-day TTL
   - `refreshing`: stale cache returned, background job enqueued
   - `pending`: no cache, background job enqueued (return empty list)

Import `RulingCache` from `app.models.ruling_cache`. Import `get_court_codes_for_gemeente` from `ecli_registry` (needed for validation that gemeente is known). The TTL constant should be `RULING_CACHE_TTL_SECONDS = 7 * 24 * 3600` defined at module level.

The endpoint requires authentication (via `get_current_active_user`) but does NOT filter by organization_id -- ruling_cache is org-agnostic.
