  <name>Task 1: Auth happy-path integration tests</name>
  <files>
    backend/tests/integration/test_auth_flow.py
  </files>
  <action>
    Create backend/tests/integration/test_auth_flow.py with comprehensive happy-path integration tests using the async_client fixture from conftest.py.

    All tests are async and use the async_client fixture which provides an httpx AsyncClient with ASGITransport pointing at the FastAPI app, with test_db overriding get_db.

    **Registration tests:**
    - test_register_success: POST /auth/register with valid data (email, password min 8 chars, organization_name). Assert 201 status, response has access_token, refresh_token, token_type="bearer". Decode access_token to verify it contains sub and organization_id claims.
    - test_register_creates_organization: Register, then use access_token to GET /auth/me. Verify response includes organization_id (non-null UUID).

    **Login tests:**
    - test_login_success: Register a user first, then POST /auth/login with same email/password. Assert 200, response has access_token and refresh_token.
    - test_login_case_insensitive_email: Register with "Test@Example.com", login with "test@example.com". Assert 200.

    **Token refresh tests:**
    - test_refresh_token_rotation: Register (get tokens), POST /auth/refresh with refresh_token. Assert 200, new access_token differs from original, new refresh_token differs from original.
    - test_refresh_revokes_old_token: Register, refresh once (get new tokens), try to refresh again with the OLD refresh_token. Assert 401 (old token was revoked during first refresh).

    **Logout tests:**
    - test_logout_success: Register, POST /auth/logout with refresh_token. Assert 200, message="Logged out successfully".
    - test_logout_then_refresh_fails: Register, logout, then try POST /auth/refresh with the same refresh_token. Assert 401 (token was revoked by logout).

    **Get me tests:**
    - test_get_me_returns_user_info: Register, GET /auth/me with Authorization: Bearer {access_token}. Assert 200, response has email, full_name, organization_id, email_verified, auth_provider.
    - test_get_me_without_token_returns_401: GET /auth/me with no Authorization header. Assert 401.

    **Full lifecycle test:**
    - test_full_auth_lifecycle: Register -> login -> /me -> refresh -> /me with new token -> logout. All steps succeed. This tests the complete flow in one test.

    **Email verification tests:**
    - test_verify_email_success: Register (user starts unverified). Create a verification token manually using create_email_verification_token(user_id, email). POST /auth/verify-email with token. Assert 200, message contains "verified". GET /auth/me and verify email_verified=True.

    **Password reset tests:**
    - test_password_reset_flow: Register with password "OldPass123!". Create reset token manually using create_password_reset_token(user_id). POST /auth/password-reset/confirm with token and new_password="NewPass123!". Assert 200. Login with new password succeeds. Login with old password fails.

    Important implementation notes:
    - Use `from app.auth.jwt import create_email_verification_token, create_password_reset_token, decode_token` for manual token creation in verification/reset tests.
    - For tests that need user_id after registration, decode the access_token to get the "sub" claim.
    - Rate limiting is disabled in tests via conftest.py fixture, so no need to worry about rate limits.
    - Registration data format: {"email": "...", "password": "...", "full_name": "...", "organization_name": "..."}
    - Login data format: {"email": "...", "password": "..."}
    - Refresh data format: {"refresh_token": "..."}
    - Each test function gets a fresh database (tables recreated) so no data leakage between tests.

<task type="auto">
  <name>Task 2: Auth error case and security integration tests</name>
  <files>
    backend/tests/integration/test_auth_errors.py
  </files>
  <action>
    Create backend/tests/integration/test_auth_errors.py with error cases, edge cases, and security feature tests.

    Uses async_client and create_test_user fixtures from conftest.py.

    **Login error tests (parametrized):**
    - test_login_invalid_credentials: Use pytest.mark.parametrize with cases:
      - ("wrong@example.com", "TestPass123!", 401, "Incorrect email or password") -- unknown email
      - ("test@example.com", "WrongPass!", 401, "Incorrect email or password") -- wrong password
      For each case: create a test user first (via create_test_user), then POST /auth/login. Assert status code and detail message.
      Note: Both cases return same error message to prevent user enumeration.

    **Registration error tests:**
    - test_register_duplicate_email: Register a user, then try to register again with same email. Assert 400, detail="Email already registered".
    - test_register_short_password: POST /auth/register with password "short" (< 8 chars). Assert 422 (Pydantic validation error).
    - test_register_invalid_email: POST /auth/register with email "not-an-email". Assert 422.
    - test_register_missing_organization_name: POST /auth/register without organization_name field. Assert 422.

    **Token security tests:**
    - test_refresh_token_reuse_detection: This tests the theft detection feature. Register user -> refresh (get new tokens, old token revoked) -> try to use the OLD refresh token again. This should:
      1. Return 401
      2. Revoke ALL remaining tokens for the user (security incident response)
      After this, even the NEW refresh token should be revoked. Verify by trying to refresh with the new token -- should return 401.

    - test_access_token_expired_returns_401: Create an expired access token manually (using jwt.encode with exp in the past). GET /auth/me with this expired token. Assert 401.

    - test_refresh_token_used_as_access_returns_401: Register, try to use the refresh_token as a Bearer token in GET /auth/me. Assert 401 (type check: refresh != access).

    **Email verification grace period test:**
    - test_login_blocked_after_grace_period: Create a user with email_verified=False and created_at set to 3 days ago (past 48h grace period) via create_test_user fixture. Attempt login. Assert 403, detail="Email verification required".
      Implementation: Use create_test_user, then manually update user.created_at in test_db to datetime.utcnow() - timedelta(days=3), await test_db.commit().

    **Disabled user test:**
    - test_login_disabled_user_returns_403: Create user with is_active=False via create_test_user(is_active=False). Login with correct credentials. Assert 403, detail="User account is disabled".

    **Password reset security tests:**
    - test_password_reset_request_unknown_email_still_200: POST /auth/password-reset/request with unknown email. Assert 200 (prevents enumeration -- always returns success).
    - test_password_reset_expired_token: Create reset token manually with expired timestamp (using jwt.encode with exp in the past). POST /auth/password-reset/confirm. Assert 400, detail contains "expired".
    - test_password_reset_revokes_all_sessions: Register user, refresh token once (so user has 2 refresh tokens in DB). Reset password. Try to refresh with either token -- both should return 401 (all sessions revoked).

    **Email verification error tests:**
    - test_verify_email_expired_token: Create expired verification token (jwt.encode with exp in the past). POST /auth/verify-email. Assert 400, detail contains "expired".
    - test_verify_email_invalid_token: POST /auth/verify-email with token="garbage". Assert 400.

    **Logout edge cases:**
    - test_logout_invalid_token_still_200: POST /auth/logout with refresh_token="invalid-garbage". Assert 200 (idempotent, graceful).
    - test_logout_already_revoked_still_200: Register, logout, logout again with same token. Assert 200 (idempotent).

    Important implementation notes:
    - For manual token creation with custom exp: `import jwt as jwt_module` then `jwt_module.encode(payload, settings.SECRET_KEY, algorithm="HS256")`
    - Import settings from app.core.config
    - Import datetime, timedelta from datetime module
    - For the grace period test, after creating user, update created_at directly on the model instance and commit
    - create_test_user fixture returns (user, org) tuple
