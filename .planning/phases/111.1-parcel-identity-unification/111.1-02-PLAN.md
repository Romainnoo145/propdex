  <action>
    Create `backend/app/tools/backfill_parcel_code.py` following the pattern from `backfill_parcel_addresses.py`.

    **CLI interface:**
    ```
    python -m app.tools.backfill_parcel_code [--gemeente GM0983] [--dry-run] [--batch-size 200]
    ```
    - `--gemeente`: Optional filter by gemeente_code (with GM prefix, stripped internally)
    - `--dry-run`: Log what would be done without writing
    - `--batch-size`: Rows per PDOK batch (default 200)

    **Phase 1: Populate parcel_cache.parcel_code from PDOK WFS**

    1. Query all `parcel_cache` rows where `parcel_code IS NULL`, ordered by `id`. If `--gemeente` provided, filter by `gemeente_code`.
    2. For each batch of rows (batch_size):
       a. For each row, check if `parcel_id` is pure numeric (regex `^\d+$`):
          - If numeric: call PDOK WFS to resolve display string
          - If NOT numeric (dash-format fallback like "HTT02-A-1234"): skip PDOK, leave parcel_code NULL
       b. PDOK WFS call (per parcel):
          ```
          GET https://service.pdok.nl/kadaster/kadastralekaart/wfs/v5_0
          ?service=WFS&version=2.0.0&request=GetFeature
          &typeName=kadastralekaart:Perceel
          &CQL_FILTER=identificatie='{parcel_id}'
          &outputFormat=application/json&count=1
          ```
       c. From response JSON, extract from `features[0].properties`:
          - `kadastrale_gemeente_waarde` (e.g. "Venlo")
          - `sectie` (e.g. "I")
          - `perceelnummer` (e.g. 6658)
          - Compose: `parcel_code = f"{kadastrale_gemeente_waarde.strip()} {sectie.strip()} {perceelnummer}"`
       d. UPDATE `parcel_cache SET parcel_code = :code WHERE id = :id`
    3. Use `asyncio.Semaphore(10)` for concurrent PDOK requests (matches area_scan.py pattern)
    4. Sleep 0.5s between batches to be polite to PDOK
    5. Use `async_session_factory()` from `app.core.database`
    6. Use direct `db.add() / db.flush() / db.commit()` pattern (NOT `async with db.begin()`)
    7. Commit every batch (not every row, not all at end)
    8. Log progress: `"Batch {n}/{total}: {resolved} resolved, {skipped} skipped (non-numeric), {failed} PDOK failures"`

    **Phase 2: Populate parcel_favorites.parcel_cache_id from parcel_code join**

    After Phase 1 completes:
    1. Run a single UPDATE statement:
       ```sql
       UPDATE parcel_favorites pf
       SET parcel_cache_id = pc.id
       FROM parcel_cache pc
       WHERE pf.parcel_id = pc.parcel_code
         AND pf.organization_id = pc.organization_id
         AND pf.parcel_cache_id IS NULL
       ```
    2. Log: `"Updated {count} favorites with parcel_cache_id FK"`
    3. Log any favorites that could NOT be matched (parcel_code not found in cache)

    **Error handling:**
    - PDOK 4xx/5xx: log warning, skip row, continue
    - PDOK response missing features: log warning, skip row
    - Database errors: log, rollback batch, continue with next batch
    - KeyboardInterrupt: commit current batch, exit cleanly

    **Stats logging at end:**
    ```
    Backfill complete:
      Total rows inspected: {N}
      parcel_code resolved: {N}
      parcel_code skipped (non-numeric): {N}
      parcel_code failed (PDOK error): {N}
      favorites FK updated: {N}
      favorites FK unmatched: {N}
    ```

    Use `from app.core.http_client import create_government_api_client` for the httpx client (matches existing backfill tools).

    IMPORTANT: The `parcel_id` in `parcel_favorites` stores the display string (e.g. "Venlo I 6658"), which is the SAME format as the new `parcel_code` in `parcel_cache`. The join `pf.parcel_id = pc.parcel_code` is correct.
