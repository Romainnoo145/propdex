<objective>
Build the government API client layer and address resolution service that converts a Dutch postcode + huisnummer into structured BAG data (address, building, geometry).

Purpose: This is the entry point for all property lookups. Users provide an address, and the system needs to resolve it through the BAG API hierarchy (address -> nummeraanduiding -> verblijfsobject -> pand) before any parallel data fetching can happen.

Output: PDOK Locatieserver client (for future autocomplete), BAG API client (address/building data), address resolver service, Pydantic schemas with Dutch postcode validation.
</objective>

  <action>
    1. Create `backend/app/government_apis/__init__.py` (empty package file).

    2. Create `backend/app/government_apis/base.py`:
       - Base error class `GovernmentAPIError(Exception)` with attributes: `source: str`, `status_code: int | None`, `message: str`.
       - Subclasses: `APINotFoundError(GovernmentAPIError)`, `APIRateLimitError(GovernmentAPIError)`, `APITimeoutError(GovernmentAPIError)`.
       - Helper function `handle_api_response(response: httpx.Response, source: str) -> dict` that:
         - Raises APINotFoundError for 404
         - Raises APIRateLimitError for 429
         - Calls response.raise_for_status() for other errors (will raise httpx.HTTPStatusError)
         - Returns response.json() on success
       - Import logging and create logger for the module.

    3. Create `backend/app/government_apis/pdok_locatieserver.py`:
       - Class `PDOKLocatieserver` with methods that take `client: httpx.AsyncClient` as first param (NOT stored on self; client comes from app.state):
         - `async def suggest(self, query: str, client: AsyncClient, rows: int = 5) -> list[dict]`:
           - GET `https://api.pdok.nl/bzk/locatieserver/search/v3_1/suggest`
           - Params: `q=query`, `rows=rows`, `fq=type:adres` (filter to addresses only)
           - Returns list of suggestion dicts from `response.docs`
         - `async def lookup(self, object_id: str, client: AsyncClient) -> dict`:
           - GET `https://api.pdok.nl/bzk/locatieserver/search/v3_1/lookup`
           - Params: `id=object_id`
           - Returns object details from `response.docs[0]`
       - No auth required for PDOK Locatieserver.
       - Use handle_api_response from base.py.

    4. Create `backend/app/government_apis/bag_api.py`:
       - Class `BAGAPIClient` with methods that take `client: httpx.AsyncClient`:
         - Private property `_headers` returning `{"X-Api-Key": settings.BAG_API_KEY, "Accept-Crs": "epsg:28992"}`.
         - Base URL constant: `BASE_URL = "https://api.bag.kadaster.nl/lvbag/individuelebevragingen/v2"`
         - `async def get_address(self, postcode: str, huisnummer: int, client: AsyncClient, huisletter: str | None = None, toevoeging: str | None = None) -> dict`:
           - GET `{BASE_URL}/adressen` with params: postcode, huisnummer, huisletter (if provided), huisnummertoevoeging (if provided)
           - Returns first address from `_embedded.adressen[0]`
           - Raises APINotFoundError if no addresses found
         - `async def get_nummeraanduiding(self, nummeraanduiding_id: str, client: AsyncClient) -> dict`:
           - GET `{BASE_URL}/nummeraanduidingen/{id}`
           - Returns full nummeraanduiding details
         - `async def get_verblijfsobject(self, verblijfsobject_id: str, client: AsyncClient) -> dict`:
           - GET `{BASE_URL}/verblijfsobjecten/{id}`
           - Returns verblijfsobject with pandId references
         - `async def get_pand(self, pand_id: str, client: AsyncClient) -> dict`:
           - GET `{BASE_URL}/panden/{id}`
           - Returns pand (building) details with geometry and construction year
       - All methods use self._headers for authentication.
       - All methods use handle_api_response from base.py.
       - Log each API call at INFO level with the endpoint being called.

    IMPORTANT: API clients do NOT create their own httpx clients. They receive the shared client from app.state.http_client. This ensures connection pooling works correctly.

  <action>
    1. Create `backend/app/schemas/__init__.py` (empty package file).

    2. Create `backend/app/schemas/address.py`:
       - `AddressInput(BaseModel)` — request schema for property lookup:
         - `postcode: str` with `@field_validator("postcode")` that validates Dutch postcode format (`^\d{4}\s?[A-Z]{2}$` after uppercasing) and normalizes to "1234 AB" format (4 digits, space, 2 uppercase letters). Raise ValueError with message "Invalid Dutch postcode format. Expected: 1234AB or 1234 AB" on failure.
         - `huisnummer: int` with `Field(gt=0, description="House number")`
         - `huisletter: str | None = None`
         - `toevoeging: str | None = None` (huisnummer addition, e.g., "bis", "A")

       - `BAGAddressResponse(BaseModel)` — structured address data returned from BAG:
         - `nummeraanduiding_id: str`
         - `verblijfsobject_id: str | None = None`
         - `straat: str`
         - `huisnummer: int`
         - `huisletter: str | None = None`
         - `toevoeging: str | None = None`
         - `postcode: str`
         - `woonplaats: str`

       - `BuildingData(BaseModel)` — building/pand details:
         - `pand_id: str`
         - `bouwjaar: int | None = None` (construction year)
         - `status: str | None = None` (e.g., "Pand in gebruik")
         - `oppervlakte: int | None = None` (surface area in m2, from verblijfsobject)
         - `gebruiksdoel: list[str] = []` (usage purpose, e.g., ["woonfunctie"])
         - `geometry: dict | None = None` (raw GeoJSON geometry from BAG)

       - `AddressResolution(BaseModel)` — complete resolution result:
         - `address: BAGAddressResponse`
         - `building: BuildingData | None = None`
         - `resolved_at: str` (ISO datetime)
         - `source: str = "bag"` (data source attribution)

    3. Create `backend/app/services/address_resolver.py`:
       - Import BAGAPIClient, cache_manager, schemas.
       - Async function `resolve_address(input: AddressInput, client: httpx.AsyncClient, organization_id: uuid.UUID, session: AsyncSession) -> AddressResolution`:
         - Step 1: Call `bag_api.get_address(postcode, huisnummer, client)` to get address data. Extract nummeraanduidingId and adresseerbaarObjectIdentificatie (verblijfsobjectId).
         - Step 2: If verblijfsobject_id exists, call `bag_api.get_verblijfsobject(id, client)` to get oppervlakte, gebruiksdoel, and pandId references.
         - Step 3: If pandId found (from verblijfsobject's `_embedded.pandIdentificaties` or similar), call `bag_api.get_pand(id, client)` to get bouwjaar, status, geometry.
         - Steps 2 and 3 are sequential (2 depends on 1, 3 depends on 2). This is intentional -- the BAG hierarchy requires chaining.
         - Wrap each step in try/except to handle partial failures gracefully. If step 2 fails, still return address without building data. If step 3 fails, return address + partial building data.
         - Use cache_manager.get_cached_or_fetch() for each BAG API call. Cache keys: `"bag:address:{postcode}:{huisnummer}"`, `"bag:verblijfsobject:{id}"`, `"bag:pand:{id}"`.
         - Return AddressResolution with all collected data and source attribution.
         - Use `datetime.utcnow().isoformat()` for resolved_at timestamp (naive UTC per Decision 13).

       - Helper function to instantiate BAGAPIClient (module-level singleton):
         `_bag_client = BAGAPIClient()`

    IMPORTANT: The resolve_address function uses cache for EACH individual API call (not the aggregate). This way, if a verblijfsobject is shared between addresses, its cached data benefits all lookups referencing it.
