Build the cadastral parcel client, property aggregator with parallel fetching, and the authenticated API endpoint that ties everything together.

Purpose: This is the user-facing endpoint that completes the core data pipeline. A user sends a postcode + huisnummer, and the system resolves the address via BAG, fetches building data and cadastral parcels in parallel, caches everything, and returns a structured property report with source attribution and staleness indicators.

Output: PDOK Cadastral client, property aggregator with asyncio.gather, POST /api/properties/lookup endpoint with JWT auth, response schemas with completeness score and cache metadata.

  <action>
    1. Create `backend/app/government_apis/pdok_cadastral.py`:
       - Class `PDOKCadastralClient` with methods taking `client: httpx.AsyncClient`:
         - Base URL: `https://api.pdok.nl/kadaster/brk-kadastrale-kaart/ogc/v1`
         - `async def get_parcels_by_bbox(self, bbox: str, client: AsyncClient, limit: int = 10) -> list[dict]`:
           - GET `{BASE_URL}/collections/perceel/items`
           - Params: `bbox=bbox`, `limit=limit`, `f=json`
           - Returns list of parcel features from `features` array
           - Each feature has: `properties` (kadastraleAanduiding, perceelnummer, etc.) and `geometry` (GeoJSON polygon)
         - `async def get_parcels_by_point(self, x: float, y: float, client: AsyncClient, distance: float = 1.0) -> list[dict]`:
           - Uses bbox constructed from point +/- distance: `f"{x-distance},{y-distance},{x+distance},{y+distance}"`
           - Calls get_parcels_by_bbox
           - This is how we'll link BAG address coordinates to cadastral parcels
       - No authentication required (free PDOK API).
       - Use handle_api_response from base.py.
       - Log API calls at INFO level.

    2. Create `backend/app/schemas/property.py`:
       - Import AddressResolution, BAGAddressResponse, BuildingData from address schemas.

       - `CadastralParcel(BaseModel)`:
         - `kadastrale_aanduiding: str | None = None` (e.g., "ASD04 S 12345")
         - `perceelnummer: str | None = None`
         - `sectie: str | None = None`
         - `oppervlakte: int | None = None` (parcel area in m2)
         - `geometry: dict | None = None` (GeoJSON)

       - `DataSourceInfo(BaseModel)`:
         - `source: str` (e.g., "BAG API v2", "PDOK Cadastral OGC API")
         - `cached_at: str | None = None` (ISO datetime)
         - `age_seconds: int | None = None`
         - `is_cached: bool = False`

       - `PropertyLookupResponse(BaseModel)`:
         - `address: BAGAddressResponse`
         - `building: BuildingData | None = None`
         - `cadastral_parcels: list[CadastralParcel] = []`
         - `data_sources: list[DataSourceInfo] = []` (one per API called)
         - `completeness_score: float` (0.0 to 1.0 — fraction of data sections that returned data)
         - `errors: list[str] = []` (human-readable error messages for failed API calls)
         - `resolved_at: str` (ISO datetime when lookup was performed)

    3. Create `backend/app/services/property_aggregator.py`:
       - Import address_resolver, pdok_cadastral, cache_manager, schemas.
       - Module-level singleton: `_cadastral_client = PDOKCadastralClient()`

       - Async function `aggregate_property_data(input: AddressInput, client: httpx.AsyncClient, organization_id: uuid.UUID, session: AsyncSession) -> PropertyLookupResponse`:
         - **Step 1 (sequential):** Resolve address using `address_resolver.resolve_address()`. This MUST succeed -- if it fails, raise HTTPException 404 "Address not found".
         - **Step 2 (parallel):** After address is resolved, fire parallel tasks using asyncio.gather with return_exceptions=True:
           - Task A: If building data not yet fully resolved (no pand geometry), fetch remaining building details. If already resolved in step 1, skip.
           - Task B: Fetch cadastral parcels. If the BAG address/building has geometry (centroid coordinates), use `get_parcels_by_point()` with those coordinates. If no coordinates available, skip (parcels will be empty).
         - **Step 3:** Collect results, handle exceptions from gather (isinstance check for Exception). Build DataSourceInfo for each API called with cache metadata.
         - Calculate completeness_score: count non-None sections (address=always 1, building=0 or 1, parcels=0 or 1) divided by total sections (3).
         - Collect error messages for failed sections into errors list.
         - Return PropertyLookupResponse with all data, sources, and completeness.

       - Use cache_manager.get_cached_or_fetch() for the cadastral parcel fetch. Cache key: `"kadaster:parcel:{x}:{y}"` with "kadaster" source (7-day TTL).

       - The parallel fetch pattern:
         ```python
         results = await asyncio.gather(
             fetch_building_details_if_needed(...),
             fetch_cadastral_parcels(...),
             return_exceptions=True
         )
         ```

    IMPORTANT design decisions:
    - Address resolution is SEQUENTIAL (must happen first to get coordinates).
    - Building detail completion and cadastral parcel fetch are PARALLEL (independent once we have address).
    - Use return_exceptions=True so one failure doesn't kill the entire request.
    - Every piece of data includes source attribution (which API it came from) and cache metadata.
