**Change 1 — Create new file `backend/app/admin/data_source_probe_orchestrator.py`** (~50 lines).

This module exports one async function `run_opportunistic_probes` that:
- Accepts `gemeente_code: str`, `cascade_uploads: list[DataSourceRow]`, `db: AsyncSession`, `name_map: dict[str, str]`
- Returns `list[DataSourceRow]` (rebuilt cascade_uploads after probe pass)
- Identifies Type A entries with `status == "missing"` from the input list
- For each missing key, acquires `pg_try_advisory_xact_lock` per (gemeente_code, source_key) using the `compute_lock_key` + `BigInteger` / `type_coerce` / `func` pattern already used in `refresh_source`
- If lock not acquired → skips (another request is mid-probe)
- Runs `probe_type_a_cascade` concurrently via `asyncio.gather` over all missing keys that acquired their lock
- For each probe result that is NOT "missing": calls `_load_or_create_row`, sets `status`, `error_message`, `last_checked = datetime.utcnow()`
- After gather: calls `await db.commit()` once
- Re-fetches all `DataSourceStatus` rows for the gemeente from DB
- Rebuilds and returns the `cascade_uploads` list using `_row_from_db` / `_synthesize_missing_row` and the `DATA_SOURCE_KEYS` catalog (Type A entries only — open_apis and paid_integrations are not the concern of this function)
