  <name>Task 1: Add on-accent CSS token and FOUC prevention script</name>
  <files>
    frontend/src/styles/index.css

  <action>
**index.css -- add `--color-on-accent` token:**

In the `@theme { }` block, after `--color-teal-accent-hover`, add:

```css
/* Fixed dark color for text on accent backgrounds — same in both modes */
--color-on-accent: oklch(0.12 0.005 270);
```

IMPORTANT: Do NOT add `--color-on-accent` to the `html.light { }` override block. The whole point is that this color stays dark regardless of theme, because amber-accent stays golden in both modes.

**index.html -- add FOUC prevention inline script:**

Add an inline `<script>` as the FIRST child of `<head>`, immediately after `<meta charset="UTF-8" />`:

```html
<script>
  (function() {
    try {
      if (localStorage.getItem('propdex-theme') === 'light') {
        document.documentElement.classList.add('light');
      }
    } catch (e) {}
  })();
</script>
```

This MUST be before any `<link>` tags or other `<script>` tags. The script reads localStorage synchronously and applies the `.light` class before the browser processes any CSS, preventing the dark-mode flash.
  </action>
  <verify>
1. `grep 'on-accent' frontend/src/styles/index.css` shows `--color-on-accent` in @theme block
2. `grep 'on-accent' frontend/src/styles/index.css` does NOT match inside the `html.light` block
3. `grep 'localStorage' frontend/index.html` shows the FOUC prevention script
4. The inline script appears BEFORE any `<link>` tags in index.html
  </verify>
  <done>
`--color-on-accent` is defined in `@theme` as a fixed dark color. The `html.light` block does NOT override it. `index.html` has an inline script in `<head>` that applies `.light` class synchronously before first paint.
  </done>
</task>
