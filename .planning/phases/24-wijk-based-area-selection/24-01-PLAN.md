  <files>backend/app/services/wijk_service.py</files>
  <action>
Create `backend/app/services/wijk_service.py` following the EXACT pattern from `gemeente_service.py`:

```python
async def get_wijken_in_gemeente(
    gemeente_code: str,
    client: httpx.AsyncClient,
) -> dict:
```

Key implementation details:
- **WFS URL**: `https://service.pdok.nl/cbs/gebiedsindelingen/2024/wfs/v1_0` (use 2024, NOT 2026 -- 2026 has incomplete wijk data)
- **typeName**: `gebiedsindelingen:wijk_gegeneraliseerd` (pre-generalized boundaries, optimized for web display)
- **srsName**: `EPSG:4326` (WGS84 for direct frontend MapLibre consumption)
- **OGC XML FILTER**: PropertyIsLike with wildcard pattern `WK{gemeente_code}%` (NOT PropertyIsEqualTo -- wijken have suffix after gemeente code)
  - Strip `GM` prefix if present: `"GM0983"` -> `"0983"`
  - Statcode pattern: `WK0983%` matches `WK098301`, `WK098302`, etc.
- **No `count` parameter** (fetch ALL wijken, typically 5-100 per gemeente)
- **Timeout**: 30 seconds (same as gemeente_service)
- **Return**: The full GeoJSON response dict (FeatureCollection) -- NOT just features list. Frontend needs the FeatureCollection wrapper.
- **Error handling**: Raise `ValueError` if no features found (consistent with gemeente_service pattern)
- **Logging**: Log gemeente code and wijk count at INFO level

CRITICAL: Use OGC XML FILTER (not CQL_FILTER). CQL_FILTER is silently ignored by PDOK CBS WFS. This was learned the hard way in Phase 23.

Example OGC filter XML:
```xml
<Filter><PropertyIsLike wildCard='%' singleChar='_' escapeChar='\\'>
  <PropertyName>statcode</PropertyName>
  <Literal>WK0983%</Literal>
</PropertyIsLike></Filter>
```
