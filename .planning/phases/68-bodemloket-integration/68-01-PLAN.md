    **Step A — Get RD coordinates from propdex database:**
    Query the propdex database (port 5434, database `propdex`) for a real parcel centroid in RD coordinates. Use a known Venlo address (or any scanned wijk) from the scan results. Example query to run against the database to get an RD centroid from a scanned parcel:

    ```bash
    cd /home/klarifai/Documents/klarifai/clientprojects/propdex/backend
    python3 -c "
    import asyncio
    import asyncpg

    async def main():
        conn = await asyncpg.connect('postgresql://postgres:postgres@localhost:5434/propdex')
        # Get a parcel with building geometry in RD (EPSG:28992)
        rows = await conn.fetch('''
            SELECT
                address,
                ST_X(ST_Centroid(geometry)) as rd_x,
                ST_Y(ST_Centroid(geometry)) as rd_y
            FROM parcel_cache
            WHERE geometry IS NOT NULL
            LIMIT 5
        ''')
        for r in rows:
            print(dict(r))
        await conn.close()

    asyncio.run(main())
    "
    ```

    Note: The database password may differ — check backend/.env for DATABASE_URL. The parcel_cache table stores geometry in EPSG:28992 (RD New). If `parcel_cache` has no geometry, fall back to using the coordinates from the RESEARCH.md live test (x=118150, y=583400, the Schiermonnikoog area used in research).

    **Step B — Run the ArcGIS REST query at both ±10m and ±25m buffers:**
    For the RD coordinates obtained above (or the fallback), run:

    ```python
    import httpx
    import json

    BASE_URL = (
        "https://gis.gdngeoservices.nl/standalone/rest/services"
        "/blk_gdn/lks_blk_rd_v1/MapServer/0/query"
    )

    def query_bodem(x, y, buffer):
        params = {
            "geometry": f"{x-buffer},{y-buffer},{x+buffer},{y+buffer}",
            "geometryType": "esriGeometryEnvelope",
            "inSR": "28992",
            "spatialRel": "esriSpatialRelIntersects",
            "outFields": "WBB_DOSSIER_DBK,SIKB_ID,TYPE_CD,VERVOLG_WBB,STATUSVER,STATUS_OORD,ADMINISTRATOR_NM,LOCATIECODE_BEVOEGD_GEZAG,BIS_LOCCODE",
            "returnGeometry": "false",
            "f": "geojson",
        }
        with httpx.Client(timeout=30.0) as client:
            r = client.get(BASE_URL, params=params)
            return r.status_code, r.json()

    # Test both buffer sizes
    x, y = <RD_X_FROM_STEP_A>, <RD_Y_FROM_STEP_A>
    for buf in [10, 25]:
        status, data = query_bodem(x, y, buf)
        print(f"Buffer ±{buf}m: HTTP {status}, features: {len(data.get('features', []))}")
        if data.get('features'):
            print(json.dumps(data['features'][0]['properties'], indent=2))
    ```

    **Buffer decision rule:** If ±10m returns the same features as ±25m → use ±10m (tighter = fewer false positives from adjacent parcels). If ±25m catches features that ±10m misses → use ±25m. If both return 0 features for this parcel (likely for most parcels — Bodemloket has sparse coverage), fall back to the Schiermonnikoog coordinates from RESEARCH.md (x=118150, y=583400) where 2 live features were confirmed.
