Create integration tests verifying ARQ pool creation and cleanup during FastAPI lifespan.

The lifespan in app/main.py creates `app.state.arq_pool` via `await create_pool(get_redis_settings())` at startup and calls `await app.state.arq_pool.close()` at shutdown. It also creates `app.state.http_client` via `create_government_api_client()`.

**Challenge:** The lifespan tries to connect to real Redis. For unit testing, we need to mock `create_pool` to avoid requiring Redis.

**Approach:** Patch `arq.create_pool` and `app.core.http_client.create_government_api_client` at the module level where they're imported in app.main. Use `unittest.mock.patch` to replace them with AsyncMock/MagicMock that return mock pool/client objects.

**Test class: TestLifecycleStartup**

- test_arq_pool_created_on_startup:
  ```python
  from unittest.mock import AsyncMock, MagicMock, patch
  import httpx

  mock_pool = AsyncMock()
  mock_pool.close = AsyncMock()
  mock_http_client = AsyncMock(spec=httpx.AsyncClient)
  mock_http_client.aclose = AsyncMock()

  with patch("app.main.create_pool", new=AsyncMock(return_value=mock_pool)), \
       patch("app.main.create_government_api_client", return_value=mock_http_client):
      from app.main import app
      async with AsyncClient(transport=ASGITransport(app=app), base_url="http://test") as client:
          # Verify pool was created
          assert app.state.arq_pool is mock_pool
          assert app.state.http_client is mock_http_client
  ```
  After context exit, verify `mock_pool.close` was awaited once (shutdown cleanup).

- test_http_client_created_on_startup: Same setup, verify `app.state.http_client` is set and is the mock client. Verify `mock_http_client.aclose` was awaited once after context exit.

- test_health_check_during_lifespan: With mocked lifespan, make GET / request, verify 200 with {"status": "ok"}.

**IMPORTANT:** Must disable rate limiter before tests (same as conftest.py pattern: `limiter.enabled = False`). Also need to clear `app.dependency_overrides` after test.

**IMPORTANT:** Since app is imported at module level and lifespan runs when AsyncClient enters context, the patches must be active BEFORE AsyncClient is created. Use the `with patch(...)` context manager wrapping the AsyncClient creation.
