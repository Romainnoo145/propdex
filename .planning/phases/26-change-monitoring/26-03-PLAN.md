    Pipeline:
    1. Create engine + session_factory (same pattern as area_scan_job — create_async_engine with pool_size=5)
    2. Create httpx.AsyncClient with timeout=30.0
    3. Load all monitored projects: `SELECT * FROM projects WHERE is_monitored=True AND gemeente_code IS NOT NULL`
    4. Group projects by gemeente_code to avoid duplicate API calls per gemeente
    5. For each gemeente:
       a. Determine `last_checked` — query the latest `detected_at` from ChangeRecord for this gemeente, fallback to `datetime.utcnow() - timedelta(days=2)` on first run
       b. Call `detect_permit_changes(gemeente_naam, last_checked, client, session)`
       c. Call `detect_zoning_changes(gemeente_code, last_checked, client, session)`
       d. For each change detected, link to ALL wijk projects under this gemeente by creating a ChangeRecord per project
       e. Handle IntegrityError on each insert (duplicate protection via unique constraint) — log and skip
       f. Flush + commit after each gemeente (don't let one failure roll back all)
    6. Return summary dict: `{"status": "completed", "gemeentes_checked": N, "total_changes": M}`

    Error handling:
    - Wrap per-gemeente processing in try/except — log error, continue to next gemeente
    - Wrap entire job in try/except/finally — always close httpx client and dispose engine
    - Log total results at end

    Use `from app.services.change_detector import detect_permit_changes, detect_zoning_changes`.
    Use `from sqlalchemy.exc import IntegrityError` for duplicate handling.

    The gemeente_naam for SRU queries: for parent projects (parent_id IS NULL), use project.name. For wijk projects, the gemeente name is the parent project's name. Group by gemeente_code and resolve the gemeente name from the parent project.
