  <action>
    Create `backend/app/services/change_detector.py` with two main functions:

    **1. `detect_permit_changes(gemeente_naam, last_checked, client, session)`:**
    - Use existing `sru_client.query_by_municipality(gemeente=gemeente_naam, record_type="Omgevingsvergunning", client=client)` to fetch permits
    - Handle pagination: if total_count > max_records, loop with start_record increments (see Pitfall 3 in research)
    - Filter records by date: parse `record["date"]` using `parse_api_date()` helper, keep only those after `last_checked`
    - Deduplicate against existing ChangeRecord entries: query DB for `external_id` values where change_type="permit" and gemeente_naam matches
    - Create ChangeRecord instances for new permits (don't add to session — caller handles that)
    - Return `list[ChangeRecord]`

    **2. `detect_zoning_changes(gemeente_code, last_checked, client, session)`:**
    - Use PDOK PLU WMS GetCapabilities to get layer metadata
    - URL: `https://service.pdok.nl/kadaster/plu/wms/v1_0?SERVICE=WMS&REQUEST=GetCapabilities`
    - Compute hash of response content (hashlib.sha256)
    - Compare against stored hash in a simple cache (use CachedAPIResponse model with cache_key=f"plu_capabilities_hash:{gemeente_code}")
    - If hash changed, create a single ChangeRecord with change_type="zoning", external_id=f"plu_update_{date}", title describing the update
    - Return `list[ChangeRecord]`

    **3. Helper `parse_api_date(date_str: str) -> datetime`:**
    - Parse ISO date string from SRU (Europe/Amsterdam timezone assumed if no tz)
    - Convert to naive UTC using `zoneinfo.ZoneInfo`
    - Per project convention: return naive UTC datetime

    Use `from app.government_apis.sru_bekendmakingen import sru_client` (existing singleton).
    Use `from app.models.change_record import ChangeRecord` for creating records.
    Use `from app.models.cached_response import CachedAPIResponse` for hash storage.
    All functions are async. Use `datetime.utcnow()` (naive UTC).

  <files>

  <action>
    **1. Create `backend/app/monitoring/__init__.py`** — empty file.

    **2. Create `backend/app/monitoring/router.py`** with these endpoints:

    Follow the pattern from `backend/app/projects/router.py` (auth, rate limiting, tenant isolation).

    ```python
    router = APIRouter(prefix="/api/monitoring", tags=["monitoring"])
    ```

    **Endpoint 1: GET /api/monitoring/changes**
    - Query params: `project_id: uuid.UUID` (required), `limit: int = 50`, `offset: int = 0`
    - Returns `ChangeRecordListResponse` — changes for a specific project, ordered by detected_at DESC
    - Filter by organization_id (tenant isolation)
    - Side effect: auto-update UserNotificationState.last_viewed_at for this user+project when changes are viewed (per locked decision: "cleared automatically when user opens/views the project folder or change detail")
    - Rate limit: 60/minute

    **Endpoint 2: GET /api/monitoring/unread**
    - No query params (uses current user)
    - Returns `UnreadDetailResponse` — total unread count + per-project breakdown
    - Logic: For each monitored project in user's org, count ChangeRecords where detected_at > user's last_viewed_at (or count ALL if no UserNotificationState exists yet)
    - Use single efficient query with subquery, NOT N+1 per-project queries
    - Rate limit: 120/minute (polled frequently from frontend)

    **Endpoint 3: POST /api/monitoring/viewed/{project_id}**
    - Upserts UserNotificationState for current user + project_id
    - Sets last_viewed_at to datetime.utcnow()
    - Returns `{"status": "ok"}`
    - Rate limit: 60/minute

    **Endpoint 4: GET /api/monitoring/projects**
    - Returns hierarchical project list for monitoring (gemeente groups with wijk children)
    - Only returns projects where is_monitored=True
    - Each project includes unread_count for current user
    - Returns `ProjectListResponse` (reuse schema with unread_count field)
    - Rate limit: 60/minute

    All endpoints require JWT auth via `get_current_active_user` + `get_current_organization_id`.
    All queries filter by organization_id.

    **3. Register router in `backend/app/main.py`:**
    Add `from app.monitoring.router import router as monitoring_router` and `app.include_router(monitoring_router)` alongside existing router registrations.
  </action>
