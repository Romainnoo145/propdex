# Roadmap: M050.5 Feature Tiering & Demo Lockdown

## Overview

Drie-tier feature-gating systeem (`demo` / `paid` / `superadmin`) om demo-users een "trailer" van Propdex te tonen ipv het volledige product. Backend-enforced (403/redact) + frontend `<TierGate>` wrapper met Pro-badge UX.

**Parallel-runnable met M049** (admin hub) en **M050** (Vindsubsidies — coordinatie: M050 bouwt feature mét tier-gate ingebakken).

**Locked scope (2026-05-16):**
- Demo ziet alleen Venlo (gemeente_code GM0983)
- Bestaande orgs met superuser → `superadmin`, anderen → `demo` (paid handmatig in te stellen)
- Backend strip via shared helper `tier_redacts(payload, tier, feature_keys)`
- Frontend gate via `<TierGate feature="..." minTier="paid">` wrapper

## Phases

- [ ] **Phase 1: Tier Infrastructure** (5 reqs) — Organization.tier enum + dependency + helpers + Alembic migratie
- [ ] **Phase 2: Backend Feature Gates** (11 reqs) — Alle paid+ endpoints op `requires_tier`; demo-strip op shared endpoints; Venlo-restrictie
- [ ] **Phase 3: Frontend TierGate + UI Gates** (15 reqs) — `<TierGate>` component + 14 gate-toepassingen + gemeente-picker restrictie
- [ ] **Phase 4: Tests + Verification** (5 reqs) — Integration tests + frontend tests + E2E smoke met screenshot

## Phase Details

### Phase 1: Tier Infrastructure (S01)

**Goal:** Fundamenteel infrastructuur waarmee elke endpoint (huidig of toekomstig) één regel weg is van tier-gating.

**Requirements:** TIER-01, TIER-02, TIER-03, TIER-04, MIG-01

**Success criteria:**
1. `Organization.tier` enum-kolom bestaat (`demo` / `paid` / `superadmin`), default `demo`
2. Alembic migratie draait clean; bestaande orgs met superuser-user → `superadmin`, anderen → `demo`
3. `get_current_org_tier(...)` dependency haalt tier op (single SELECT, no caching needed initially)
4. `requires_tier(min_tier)` decorator-style FastAPI dependency raised HTTPException(403) bij onvoldoende tier
5. `tier_redacts(payload: dict, tier, feature_keys: set[str])` strip de keys uit payload voor `demo` tier — pure helper, getest in isolation
6. Unit tests dekken alle tier-ladder paden (demo < paid < superadmin)

**Depends on:** Niets (eerste phase) — Phase 04.2 `expose_score_internals` blijft een aparte axis (kan later geïntegreerd worden, niet in deze milestone)

**Coordination:** Voor het mergen van P1, de M050 agent informeren dat tier-infra klaar is — vanaf dan kan M050 z'n Vindsubsidies-feature mét `requires_tier("paid")` bouwen.

### Phase 2: Backend Feature Gates (S02)

**Goal:** Elke paid+ endpoint returnt 403 voor demo; shared endpoints redacten gestrip data; Venlo-restrictie op map-data.

**Requirements:** API-01 t/m API-11

**Success criteria:**
1. Eigendom, subsidies, jurisprudentie, reports, favorites, custom-profile, document-upload, scan-creation endpoints returnen 403 voor demo (één test per endpoint volstaat)
2. ScanResultItem + ParcelAtPointResponse strip `vacancy_*`, `market_signals`, `opportunity_signals`, `building_metrics` voor demo
3. Tile endpoint + at-point endpoint controlleren `gemeente_code` tegen tier — demo krijgt 403 voor non-Venlo
4. Geen regressies op paid+/superadmin paths (existing integration tests blijven groen)

**Depends on:** Phase 1 (infrastructuur)

**Parallel-eligible met Phase 3:** Backend en frontend gaten worden simultaan dichtgezet — geen file-overlap.

### Phase 3: Frontend TierGate + UI Gates (S03)

**Goal:** `<TierGate>` component + 14 gated UI-elementen + Pro-badge UX die converteert ipv frustreert.

**Requirements:** UI-01 t/m UI-15

**Success criteria:**
1. `<TierGate feature="..." minTier="paid">{children}</TierGate>` rendert Pro-badge wanneer current tier onvoldoende — children verborgen, lock-icon (Amber) + "Beschikbaar in Pro" tekst
2. Pro-badge klik opent kleine modal: "Upgrade naar Pro" + mailto:info@klarifai.nl link (geen self-service in v1)
3. Eigendom, Marktsignalen, Opportunities, Building Metrics, Risico-tab, Dossiers-tab, Subsidies, Jurisprudentie cards: alle gegated met TierGate
4. Reports + Favorites + custom-profile + document-upload buttons gegated of hidden (zie matrix)
5. Map gemeente-picker: demo ziet alleen Venlo enabled, andere gemeenten greyed met Pro-badge tooltip
6. Score breakdown modal: gedrag uit Phase 04.2 blijft (paid ziet redacted, superadmin volledig)

**Depends on:** Phase 1 (tier infra) — UI moet weten welke tier de current user heeft via `useCurrentOrgTier` hook

**Parallel-eligible met Phase 2.**

### Phase 4: Tests + Verification (S04)

**Goal:** End-to-end bewijs dat demo de juiste 16 dingen niet ziet en de juiste paar dingen wel.

**Requirements:** TEST-01 t/m TEST-05

**Success criteria:**
1. Backend integration tests: 1 per paid+ endpoint-categorie + 1 redaction-test + 1 Venlo-restrictie test
2. Frontend test: `<TierGate>` rendert correct voor alle 3 tiers
3. E2E smoke: login als `demo@klarifai.nl`, navigeer naar parcel detail in Venlo, screenshot bewijst Pro-badges op alle gated cards
4. Geen regressies in M049 of M050 test suites (worden parallel ontwikkeld)

**Depends on:** Phase 2 + Phase 3
