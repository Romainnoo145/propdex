## Datamodel — nieuwe tabellen + kolommen

### `brk_ownership_records` (NEW — persist M050/S01)
```sql
CREATE TABLE brk_ownership_records (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id),
  parcel_id VARCHAR(64) NOT NULL,  -- BAG-style ID
  eigenaar_type VARCHAR(32) NOT NULL,  -- 'rechtspersoon', 'overheid', 'privé'
  eigenaar_naam TEXT,  -- NULL voor 'privé' (AVG)
  kvk_nummer VARCHAR(8),
  statutaire_zetel TEXT,
  zakelijk_recht_type VARCHAR(32),
  aandeel TEXT,
  koopsom NUMERIC,
  koopjaar INTEGER,
  heeft_hypotheek BOOLEAN,
  raw_brk_response JSONB,  -- voor debugging
  fetched_at TIMESTAMP NOT NULL DEFAULT NOW(),
  soft_deleted_at TIMESTAMP,  -- Q7 retention
  hard_delete_after TIMESTAMP,  -- Q7: fetched_at + 30 dgn als unfavorited
  UNIQUE (organization_id, parcel_id, fetched_at)
);
CREATE INDEX idx_brk_org_parcel ON brk_ownership_records (organization_id, parcel_id);
CREATE INDEX idx_brk_hard_delete ON brk_ownership_records (hard_delete_after) WHERE soft_deleted_at IS NOT NULL;
```

ARQ cron-job: `brk_retention_cleanup` daily, hard-delete waar `hard_delete_after < NOW()`.

### `brief_messages` (NEW — M050/S04+S05)
```sql
CREATE TABLE brief_messages (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id),
  parcel_id VARCHAR(64) NOT NULL,
  template_key VARCHAR(64) NOT NULL,  -- 'cold-outreach', 'follow-up', 'verkenning'
  ai_personalized BOOLEAN NOT NULL DEFAULT FALSE,
  body_markdown TEXT NOT NULL,  -- final partner-approved content
  recipient_name TEXT,
  recipient_address JSONB,  -- {street, number, postal_code, city}
  partner_branding_id UUID REFERENCES partner_branding(id),
  postnl_message_id VARCHAR(64),  -- external ref na verzending
  status VARCHAR(32) NOT NULL DEFAULT 'draft',  -- draft, queued, sent, in_transit, delivered, failed, returned
  draft_idempotency_key UUID UNIQUE,  -- voorkomt dubbele submit
  created_at TIMESTAMP NOT NULL DEFAULT NOW(),
  sent_at TIMESTAMP,
  UNIQUE (organization_id, parcel_id, draft_idempotency_key)
);
CREATE INDEX idx_brief_org_status ON brief_messages (organization_id, status);
CREATE INDEX idx_brief_parcel ON brief_messages (organization_id, parcel_id);
```

### `brief_delivery_events` (NEW — M050/S05 webhook idempotency)
```sql
CREATE TABLE brief_delivery_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  brief_message_id UUID NOT NULL REFERENCES brief_messages(id),
  external_event_id VARCHAR(128) NOT NULL,  -- PostNL event identifier
  status VARCHAR(32) NOT NULL,
  occurred_at TIMESTAMP NOT NULL,
  payload JSONB NOT NULL,
  received_at TIMESTAMP NOT NULL DEFAULT NOW(),
  UNIQUE (external_event_id)
);
CREATE INDEX idx_delivery_events_brief ON brief_delivery_events (brief_message_id, occurred_at);
```

### `ai_generation_audit` (NEW — D1 AI governance)
```sql
CREATE TABLE ai_generation_audit (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id),
  brief_message_id UUID REFERENCES brief_messages(id),
  input_schema_version VARCHAR(16) NOT NULL,
  input_hash VARCHAR(64) NOT NULL,  -- SHA256 van structured input
  ai_output_raw TEXT NOT NULL,
  partner_edited_output TEXT,  -- NULL als partner geen edits
  claude_model VARCHAR(64) NOT NULL,
  refused BOOLEAN NOT NULL DEFAULT FALSE,
  refusal_reason TEXT,
  generation_duration_ms INTEGER,
  created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_ai_audit_org ON ai_generation_audit (organization_id, created_at);
```

### `partner_branding` (NEW — E5)

CREATE TABLE partner_branding (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL UNIQUE REFERENCES organizations(id),
  logo_url TEXT,  -- S3/Blob storage URL
  voettekst TEXT,
  lettertype VARCHAR(64) DEFAULT 'PlusJakartaSans',

### `tier_quota_counters` (NEW — M050.5/S02)
```sql
CREATE TABLE tier_quota_counters (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id UUID NOT NULL REFERENCES organizations(id),
  source_key VARCHAR(64) NOT NULL,  -- 'brk-eigendom', 'brief-postnl', etc
  period_start DATE NOT NULL,  -- first of month, UTC
  count INTEGER NOT NULL DEFAULT 0,
  limit_value INTEGER NOT NULL,
  updated_at TIMESTAMP NOT NULL DEFAULT NOW(),
  UNIQUE (organization_id, source_key, period_start)
);
CREATE INDEX idx_quota_org_period ON tier_quota_counters (organization_id, period_start);
```

ARQ cron-job: `quota_monthly_reset` op 1e van maand 00:00 UTC, voegt nieuwe row per (org, source_key) toe op basis van huidige tier-limits.

### Quota race-condition prevention
```
Concurrent request 1                Concurrent request 2
 │                                   │
 ▼ tx start                          ▼ tx start
 UPDATE tier_quota_counters          UPDATE tier_quota_counters
   SET count = count + 1               SET count = count + 1
   WHERE org=X AND key='brief'         WHERE org=X AND key='brief'
     AND count < limit                   AND count < limit
   RETURNING count                     RETURNING count
 │                                   │
 (Postgres serializes)               (waits for lock release)
 │                                   │
 returns count=5/5 ✓                 returns count=5/5 (was 5, +1=6 but check fails)
 │                                   │
 INSERT brief_messages               returns rows-affected=0
 │                                   │
 commit                              raise QuotaExceeded → 429 + upgrade
 │                                   │
 200 brief sent                      429 hard-cap
```

### Multi-tenant isolation
```
Every endpoint:
  - JWT decode → user.organization_id
  - Service-layer: query .filter(organization_id == user.org_id)
  - Postgres RLS-policies bevestigen org-isolatie at-DB-laag
  - Tests: cross-org-access altijd 404 (niet 403, om geen leak van bestaan)
```

**Execution order:**
- **Phase 1 (week 1-3):** Lanes A + B + C launch parallel in worktrees

- **Phase 3 (week 8-11):** Lane F wires everything once A+B+C+D+E merged.
- **Phase 4 (week 11-13):** Lane G verification + GA-prep.

**Conflict flags:**
- Lane B + Lane C beide raken `app/api/endpoints/` (new files only — no conflict if naming-discipline maintained)
- Lane D + Lane E beide refereren `partner_branding` table (D=write, E=read — geen conflict)
